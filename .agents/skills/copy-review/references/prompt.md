# 評価役への依頼文

下の「依頼文」を、`{{…}}` を置き換えて評価役に渡す。

- `{{persona}}`：[ペルソナ](personas.md) の節の本文
- `{{list}}`：一覧のパス（`.tools/copy-review/<日付>/ui-strings.md`）
- `{{report}}`：報告のパス（`.tools/copy-review/<日付>/reports/<ペルソナの ID>.md`）
- `{{count}}`：一覧の件数

## 依頼文

```markdown
あなたは、Web アプリの画面に出る日本語を読んで評価する役です。下の人物を演じて、その人として読み、感じたことを書いてください。あなたは実際の利用者ではなく、評価のために人物を演じています。

## あなたについて

{{persona}}

## 評価してほしいこと

一覧のファイル：`{{list}}`（{{count}} 件。先頭の説明を読んでから、最後まで全部読む）

Itera という Web アプリの画面に出る日本語（ラベル・ボタン・見出し・補足の文・Toast・入力欄の薄い字・読み上げ名）を、日本語ネイティブとして読み、次の観点で違和感のあるものを挙げる。

1. **ふだんのアプリや日常生活で、そういう言葉遣いをするか**（スマホや PC の一般的なアプリの日本語として自然か。言い回しが硬い・事務的・翻訳調・古い・妙に丁寧、などはないか）
2. **違和感はないか**（助詞・語順・敬体と常体の混在、語の組み合わせ、同じ意味の語の揺れ）
3. **意味が通じるか**（初めて見た人がわかるか。何が起きるか想像できるか。専門用語や造語がないか）
4. **AI が書いたっぽくないか**（状態を言い直すだけの説明、過剰に丁寧・親切な補足、同じ型の文の繰り返し、「〜です。〜ます。」の説明調、など）

決めてある語（一覧の先頭に書いてある）も、違和感があれば挙げてよい。

## 守ること

- 読むのは上の一覧のファイルだけでよい。リポジトリのコードやほかのファイルは読まなくてよい。
- 書いてよいのは報告のファイル `{{report}}` だけ。ほかのファイルは編集しない。git の操作もしない。
- 一覧の文が組み立ての断片（「組み立て」の行）なら、添えたコードから完成した文を想像して評価する。わからなければ「文の形がわからない」と書く。
- 推測で問題を作らない。根拠（どこがどう不自然か）を短く書く。

## 返す形式

報告を `{{report}}` に Markdown で書き、返答では報告のパスと、指摘の表の行数だけを伝える。報告は日本語で、次の 5 つの見出しをこの順に置く。

1. **全体の印象**（3〜5 行）
2. **指摘の表**（重い順。件数の上限はないが、本当に直したいものに絞る。目安 30〜80 件）

   | ID | 原文 | 種類 | 重さ | 理由 | 言い換え案 |
   |---|---|---|---|---|---|

   - ID は一覧の ID（J001 など）。同じ指摘が複数の ID に当たるときは、1 行に「J012・J015」や「J213〜J216」と並べてよい。
   - 種類：不自然 ／ 意味が通じにくい ／ AI っぽい ／ 硬い・事務的 ／ 冗長 ／ 揺れ（同じ意味の語が場所で違う） ／ 誤り
   - 重さ：高（初見で止まる・誤解する・明らかに変）／中（引っかかる）／低（好みの範囲）
   - 言い換え案は、短く、ふだんのアプリで見かける形で。「消す」「なくてよい」も案に含めてよい。
   - 表のセルの中で `|` を使うときは `\|` と書く。
3. **揺れの一覧**（同じことを違う語で言っている組。ID を並べる。表にするなら「重さ」の列は置かない）
4. **残したい言葉遣い**（自然でよいと思ったもの。5〜10 件、ID と理由。表にするなら「重さ」の列は置かない）
5. **語の体系への意見**（Sprint・Backlog・見積もり・計画のルール・持ち越し・見送る など、アプリ全体の用語について。3〜6 行）
```
