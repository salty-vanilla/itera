# 画面の文言を評価する

画面に出る日本語を全件抜き出し、評価役に「ふだんそう言うか」「違和感はないか」「意味が通じるか」「AI が書いたっぽくないか」の 4 つの観点で読ませる。評価役は実際の利用者ではない。人数の多さは「多くの観点から見て引っかかる」ことを示すだけで、利用者で確かめたことにはならない。要約にも必ずそう書く。

用語と書き方の正本は `docs/design/content.md`。評価役の案がそこで決めた語とぶつかるときは、要約でその旨を示し、変えるかどうかはオーナーが決める。

## いつ回すか

- 画面の文言を多く変えた Issue のまとまりがマージされたあと
- `feature/web-ux` を main へ入れる前
- オーナーが頼んだとき

1 つの Issue の文言を確かめるだけなら、この Skill ではなく通常のレビューで足りる。

## 手順

結果は `.tools/copy-review/<日付>/` に置く（`.tools/` は Git 管理外）。同じ日に 2 回回すときは `pnpm copy:list --out .tools/copy-review/<日付>-2` のように分ける。

1. **一覧を作る**：ルートで `pnpm copy:list` を実行する。`ui-strings.md`（評価用。ID を振り、画面ごとにまとめ、先頭にアプリの説明と決めてある語を載せる）と `ui-strings.json`（集計用）ができる。件数と、前回からの増減を控える。
2. **評価役を起動する**：[ペルソナ](references/personas.md) の 7 体を、1 つのメッセージで並列に起動する（Agent tool、`subagent_type: general-purpose`、`model` はペルソナの表の値）。依頼文は [依頼文](references/prompt.md) の本文に、ペルソナの節と、一覧と報告のパスを差し込んだもの。会話の履歴や、前回の評価の結果は渡さない。fork は使わない。
   - 評価役は一覧を読んで、報告を `.tools/copy-review/<日付>/reports/<ペルソナの ID>.md` に書く。それ以外のファイルを編集しない。
   - 評価役から報告が返らない・形式が崩れているときは、同じ評価役を `SendMessage` で 1 回だけ再開して直させる。それでも足りなければ、その評価役を除いて集計し、要約に書く。
   - Codex などほかのモデルを評価役に足すのは任意。足すときも依頼文と返す形式は同じにし、報告を同じ `reports/` に置く。
3. **集計する**：`node .agents/skills/copy-review/scripts/tally.mjs .tools/copy-review/<日付>` を実行する。各報告の指摘の表（ID と重さの列がある表）を読み、評価役ごとに ID を 1 回ずつ数え、挙げた人数の多い順に並べた `tally.md` と `tally.json` を書く。「J213〜J216」のような範囲は間の ID をすべて数える。
4. **要約する**：`tally.md` と各報告を読み、メインセッションが `summary.md` を書く。形は下の「要約の形」。
5. **オーナーに渡す**：`summary.md` のテーマの一覧（見出しと人数）をオーナーに示し、どれを直すかを選んでもらう。選ばれたテーマは `issue-harness` Skill の要件整理で Issue にする。この Skill の中で Issue を起票しない。画面の文言を直さない。

## 要約の形

`summary.md` は次の順に書く。

1. 対象（ブランチと commit、件数）、評価役の表（ペルソナ・実体のモデル・挙げた ID の数）、挙げた人数ごとの件数
2. 「評価役は実際の利用者ではなく、ペルソナを演じた LLM である」という一文
3. テーマ（合意の多い順）。テーマごとに、何が起きているかを 1〜3 行、挙げた人数（「7 人全員」「5〜7 人」）、表（ID ／ いまの文言 → 多くの評価役の案）。`content.md` で決めた語やオーナーの過去の決定とぶつかる案は、その旨を添える
4. 評価役が「残したい」とした言葉遣い（複数の評価役が挙げたもの）
5. 全件の集計（`tally.md` の表を貼るか、パスを示す）

テーマにするのは、複数の評価役が同じ方向の直し方を挙げたものだけ。1 人だけの指摘は全件の集計に残し、テーマにしない。

## 1 体だけで試すとき

依頼文やペルソナを変えたあとは、7 体を回す前に 1 体（Sonnet）で回し、報告が集計できる形か（`tally.mjs` が評価役の ID の数を 0 より大きく数え、一覧にない ID が 0 件か）を確かめる。`tally.mjs` を変えたら `tooling/copy/tally.test.mjs` も直す。
