# 画面の文言を書く

文言の正本は `docs/design/content.md`。この Skill は書く手順だけを決め、語や型を写さない。語や型を足す・変えるときは content.md を Issue で直す。

## 手順

1. **content.md を読む。** 「1. 原則」（書き方の決まり 10 項目）、「2. 語彙」（用語、週の呼び名、使わない語、「」で囲む語、未決の語）、「3. 型」の書く部品の節。語の意味が要るときは `docs/domain/domain-model.md` の用語表。
2. **部品の型に沿って書く。** ボタン・Toast・見出し・空の状態・補足・入力欄・確認の Dialog・操作できない理由・読み上げ名のどれかを決め、その節の形にする。語は用語表の「画面の語」を使う。未決の語は、用語表の語のまま書く。
3. **`pnpm copy:lint` を実行する。** 自分が足した・変えた文言の警告を読む。
   - 確実の規則（使わない語、「」なし、記号）は直す。
   - 目安の規則（長い文、「〜ます。」の連続、安心させる型）は、文を分けるか消せないかを考える。残すなら理由を言えるようにする。
   - 規則が合わない箇所だけ、その行か 1 行上に `copy-lint-ignore <規則> -- <理由>` を書く。誤検知が規則や表のせいなら、除外せずに規則か content.md を直す Issue にする。
4. **自己点検をする。** 変えた文言を 1 つずつ読んで確かめる。
   - ふだんの会話で、その言い方をするか。
   - 消しても意味が変わらない文はないか（状態の言い直し、安心させる一文、見た目の実況、起きないことの断り）。
   - 同じものを、見出し・ラベル・本文・Toast・読み上げ名で同じ語で呼んでいるか。
   - 補足は、行き先・期限・数のように情報を足しているか。
   - 読み上げ名（`aria-label`、`sr-only`）は、画面の語と同じか。
5. **迷う語はオーナーに聞く。** content.md で決まらない語は、2〜3 案と、それぞれの違いを 1 行ずつ示して聞く。説明の文を足して埋めない。未決の語に当たるときも同じ。

## PR に書くこと

語を変えたら、PR 本文に旧 → 新の表を置く（場所・旧・新・理由）。`pnpm copy:lint` の警告のうち、残したものと理由も書く。
