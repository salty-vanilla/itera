# 画面のパターン

更新：2026-09-27（Backlog の完了を元に戻す、Issue #47）。2026-09-26 に DESIGN.md v0.2 から分離。

Backlog・Planning・Today・Retro の画面の組み立て方。見た目と部品は [DESIGN.md](../../DESIGN.md)、意味と操作の種類は [PRD](../requirements/prd.md) と [ドメインモデル](../domain/domain-model.md) が正。UI v0.1 モックは当たり付けで、ここに書いた構成を実装して触りながら削る（PRD §12）。

## 共通

- 画面ごとに「決めていること」を 1 つだけ見出し（`display-m`）にする（Planning：「今週、何を進めますか」→「今週、どんな状態にしたいか」→「この計画で、進められそうか」、Retro：「今週、何が起きたか」）。
- Sprint の画面（Planning / Today / Retro）の Area 名は Sprint 確定時の名前で固定し、Backlog は現在の名前を出す（ドメインモデル F5）。確定前の Planning は現在の名前。
- 容量の超過は Planning だけで扱う。Today と Backlog では超過を表示しない（不変条件 25）。
- 持ち越し・見送り・超過・「できなかった」は事実として中立に書き、人格評価のように見せない。

## Backlog

active な Task を眺めるビュー。Sprint や Today に入れても消えない（不変条件 2）。

- **Capture**：上部の Task Quick Add で、タイトルだけですぐ追加し、続けて入力できる。Area・期限・Estimate・優先度は後から。未設定でも正常で、空欄を「—」で埋めない。
- **Browse**：Area の Filter と、切り口「すべて / 期限が近い / 期限超過 / 持ち越し / 繰り返し / 領域なし」。優先度だけで既定の並び順を決めない。今の Sprint に入っている Task には「今週」と出す。繰り返し Task は Rule ごとに 1 行（「毎週 土 · 次は 10/3 (土)」）で、未来の回を並べない。
- **Organize**：行を開くと、desktop は一覧を見失わない右 Drawer、compact は Bottom Sheet。タイトル、説明、Area、期限、優先度、Estimate、繰り返し、Subtask、アーカイブを編集する。Estimate の提案があれば Agent 提案で出し、下限・中央・上限のどれかを採用するか、値を直して採用（編集して採用）できる。採用・編集して採用・却下の後は 1 行と「元に戻す」を残す（agent-ui.md）。繰り返しの Rule を変えたら「次の Sprint から反映」と書く。
- **今日へ**：Sprint 外の Task を「今日へ」入れると、1 操作で今の Sprint に Sprint 中の追加として入り、今日の選択にもなる。確認 Dialog も容量の警告も出さない。行に「今週」「Sprint 中に追加」。
- **完了**：今の Sprint の Task を Backlog から完了すると、その Sprint と今日の完了にも反映する（Today の「済んだもの」に出る）。完了した行は一覧から消え、その位置に「「タイトル」を完了にしました」の 1 行と「元に戻す」ボタンを残す（Toast にはしない。ほかの操作をするか画面を離れると消える）。元に戻すと完了前の状態に戻る（ドメインモデル F29）。

## Sprint Planning

最重要の体験。1 つの workspace が **選ぶ（Pick）→ 整える（Shape）→ 確かめる（Check）** と自然に変化する。強制のウィザードにせず、どの段階にも戻れる。

### 画面構成（wide）

| 領域 | 密度 | 中身 |
| --- | --- | --- |
| Sprint Header | — | Status「計画中 · 未確定」（draft の破線 Tag）、タイトル（`display-l`）、期間、段階表示（路線図の形。現在の段階は黄の印）、操作（変更履歴 / Agent に計画案を依頼 / 「Sprint を確定」= 唯一の Primary） |
| Backlog（左、`canvas-subtle`） | Task density | Task Quick Add、Filter、グループ（持ち越し → 期限が近い → 今週発生する繰り返し → そのほか）、□ で今週へ選ぶ |
| Sprint（中央、`canvas`、最大 680px） | Thinking space | 段階ごとの見出し（`display-m`）、Area ごとの Goal と選んだ Task |
| 時間の見通し（右） | Thinking space（狭い） | 前回の改善策と有効な計画基準、可用時間と Capacity、Agent 提案 |

### 選ぶ（Pick）

- Backlog、持ち越し、期限、今週発生する繰り返しを眺め、□ で今週へ選ぶ。選ぶと行が `here-subtle` とチェックになり、中央の該当する Area に現れる。Toast「〜を今週に入れました · 元に戻す」。
- 今週発生する繰り返しの回は、既定で選択済み。不要な回は外せる（外した回は Today にも Retro の事実にも出ない）。
- 持ち越しは自動で入らない。「持ち越し」グループの候補として出し、本人が選ぶ。
- その場でタスクを追加・編集できる（Planning を中断しない）。追加したタスクは選択済みで入る。Estimate は「未見積」で入り、Capacity に「未見積 1件は合計に含まれていません」。
- Goal の入力をこの段階で求めない。前回の改善策（表示だけ）と有効な計画基準を、右ペインの上部に出す。
- Capacity は主役にしない。選んだ Task の合計と可用時間をヘッダーに控えめに出す。
- 一括選択はグループ見出しの Checkbox（indeterminate あり）。解除は中央の行メニュー「今週から外す」でもでき、どちらも元に戻せる。
- Backlog が空の初回は、クイック追加を大きく（`control-lg`）表示して始める。

### 整える（Shape）

- Area ごとに Goal と選んだ Task を同時に見ながら編集する。左に Backlog を細く残し、行き来できるようにする。
- Goal は **Area ごとに任意**。全体 Goal の入力欄は作らない。空の Area は「+ Goal を書く」と「この領域の Goal は任意です。タスクだけでも計画できます。」。
- 編集は `body-l` の Textarea（ラベル「Goal（今週の終わりにどんな状態にしたいか）」、help は「〜な状態にする」の形の推奨）。保存すると `goal` で組み直す。
- Task は「Goal に紐づく / 紐づかない」を選べる。Planning で選んだ繰り返しでない Task の既定は「紐づく」、繰り返しと Sprint 中の追加は「紐づかない」。確定時に Goal のない Area の Task は「紐づかない」になる。紐づかない Task も時間の合計に含め、薄くしたり除外を促したりしない。
- Goal を書いた後に Task を増減してよい。Agent の Goal 文案は Goal の直下に Agent 提案で出す（採用しても `body-l` → 保存で `goal`）。

### 確かめる（Check）

- 見出し「この計画で、進められそうか」。Area ごとに Goal・Task・計画値を並べ、右に Capacity。
- 可用時間は本人が入力する。未入力なら「可用時間を入力すると、計画との差を表示します。」
- 計画値の合計は幅のまま（「16.5–18.5h」）、残りは「−1 〜 1h」。状態は ok / tight / over / unknown（DESIGN.md Capacity Indicator）。内訳は Area ごと。
- 幅がある場合は「何が上振れすると超過するか」を書く（例：「計画基準で『関連論文を 3 本読む』を上限 5h で計算しています。下限どおりなら 1.5h の余裕があります。」）。調整案は「調整案を見る」で開く段階表示にし、強制しない。
- 有効な計画基準があれば、対象・幅の扱い・「今回の時間の判断に使う」Switch と効果を出す。基準を使っても Estimate は変わらないことを書く。
- 超過していても確定できる。止めずに、確定の Dialog で再提示する。

### Agent の計画案

- 「Agent に計画案を依頼」または外部 Agent から届いた計画案は、ヘッダーの 1 行「Agent 提案 · 外部 Agent の計画案が 1件あります · 現在の計画との差分を見る」（UI v0.1 モック）と、右ペインの Agent 提案（要約＋「差分を確認」）で知らせる。ヘッダーの表示は破線の小さな「Agent 提案」の印と `ink-muted` の文字にし、「現在の計画との差分を見る」だけをリンクにする。目立たせない（PRD §12）。
- 「差分を確認」で右 Drawer（compact は全画面）に計画案の差分。行ごとに選び「選んだ N件を計画に反映」。反映しても Sprint は確定しない。Capacity は反映後の値で出す。
- 計画案の作成後に Backlog が変わったら、Notice（info）「計画案の作成後に Backlog が変わりました。差分を再確認してください」。

### 実装で決めること（Planning）

- 確定前の計画値（プレビュー）を実線と破線のどちらで描くか。破線は「本人がまだ決めていない」値（Agent 提案と下書き）の意味なので、本人の選択から計算したプレビューを破線にするかは、Planning の最初の実装 Issue で決める。
- 整える・確かめる段階で左の Backlog をどこまで細くするか。

### 確定

- Primary「Sprint を確定」（⌘/Ctrl+Enter）→ Dialog（md）で要約：Area ごとの Goal、Task の件数（うち Goal に紐づかない件数）、計画値の合計、可用時間、計画基準を使うか、注意（tight / over、未見積）。
- ボタンは Secondary「戻って調整」と Primary「Sprint を確定」。初期フォーカスは「戻って調整」。
- 前の Sprint の Retro が終わっていなければ、確定ボタンを無効にし、理由（「前の Sprint の Retro を完了すると確定できます」）と Retro への導線を添える。下書きの編集はできる。
- 確定後：Toast「Sprint 14 を確定しました」、Status を「実行中」（実線）に、Today への導線。Goal の文と可用時間は確定後も変えられ、変更は履歴に残る（Dialog に「確定後も Goal と可用時間は変更できます」）。

### compact

段階ごとに画面を分けてよいが、どの段階にも自由に移れ、「次へ」を必須の順路にしない（DESIGN.md Layout）。Capacity は整える・確かめるの画面上部に 1 行（「残り −1 〜 1h · 超える可能性」）で見せる。

## Today

毎日使う軽い画面。日次の計画やタイムトラッキングにしない。スマートフォンで完結すること。

- 上部：「Sprint 14 · 2日目 / 7日」（`meta`）、日付（`display-m`「9月29日（火）」）、Progress（「今週の完了 5 / 18件」）。今日の残り件数と見込み時間の合計を出してよいが、日次の容量を入力させたり超過を判定したりしない。
- 今週の Goal を `reflection` で Area の路線記号付きで背景として見せる（Goal のない Area は出さない）。主役は「今日やる Task」。
- **今日やる**：本人が「今週の残り」の行の先頭に常に見える「今日へ」のボタンで選ぶ（□ は使わない。UI v0.1 モック）。当日発生する繰り返しの回は、Planning で外していなければ自動で出る。前日に「今日はここまで」にした Task は「昨日の続き」として候補の上に出すが、自動では入れない。
- **日次の操作**：完了（○）を常時見せ、それ以外はメニューと詳細から。
  - 開始
  - 完了：○ が塗られ、タイトルが `ink-subtle`＋取り消し線。Toast は出さない。もう一度押すと取り消し。
  - 今日はここまで：作業したが未完了。任意で実績時間を残せる。
  - 今日は見送る：今日やらないと本人が決めた。
  - 今日から外す：選び直し。見送りには数えない。
  - スキップ：繰り返しの回だけ（○ に「−」＋「スキップ」）。
- 同じ Task を選んだ機会で見送りが続いたら「N回続けて見送り」と中立に出す（`ink-muted`）。
- **実績時間**：任意。完了後か「今日はここまで」のときに軽く追記できる。ストップウォッチを必須にしない。
- **追加**：画面下部の sticky 入力「タスクを追加」（タイトルと Area 程度）。追加した Task は Sprint 中の追加として今の Sprint に入り、同時に今日やるにも入る（不変条件 26）。
- **割り込み**：Task の行とは別の入口（「割り込みを記録」）から、短いメモと任意の時間を Bottom Sheet で残す。記録しても今日の予定を組み替えない。
- desktop の Today も同じ構造を 1 カラム（最大 720px）で表示し、右に Sprint の Goal の要約を置く。

### 実装で決めること

PRD とドメインモデルが見た目を決めていないので、Today の最初の実装 Issue でオーナーと決める。

- 開始・今日はここまで・今日は見送る の行の見た目（アイコン、時刻、置き場所）。「今日はここまで」「今日は見送る」の Task は今週の残りに戻る（不変条件 22）。
- 「済んだもの」の出し方（今日完了した Task と Backlog から完了した Task）。
- 実績時間を入力する面（Popover か Bottom Sheet か）と、スマートフォンで「今日は見送る」を片手で行える位置（PRD §8）。

### 基準画面（compact、390px）

Sprint と日付 → Progress → 今週の Goal → 今日のタスク（○ で完了、48px 行、44px ターゲット、行の操作 `…` は常時表示）→ 昨日の続き・今週の残り → sticky のクイック追加（44px）→ 下部タブバー。確認点：44px ターゲット / 入力文字 16px / hover に依存しない / Floating Action Button を置かない / 完了時に祝福の演出をしない。

## Retro

Planning と同じくらい重要な体験。反省文や成績表ではなく、**今週の事実から次の Sprint で試す変更を 1 つ決める** 場所。1 つの workspace が **事実を見る → 振り返る → 引き継ぐ** と変化する。Thinking space（`display-m` の見出しと `reflection` の本文、`spacing.8`〜`spacing.12` の余白、読み物は最大 720px）。

### 事実を見る

- 見出し「今週、何が起きたか」。最上部に Sprint Summary（完了 / 持ち越し / スキップ / Sprint 中の追加 / 計画値の合計と可用時間）。実績は入力済みのものだけと補足に書く。
- 今回の計画基準：名前、Planning 時の扱い、結果（例：「研究 2 件のうち 1 件を持ち越し（計画値 5h・実績 4.5h）」）。
- Area ごとに：Goal 文（`goal`）と自己判定（RadioGroup「できた / 一部できた / できなかった / 判断しない」、既定なし）、Task の表（Estimate / 計画値 / 実績 / 結果）、Goal に紐づかなかった Task、繰り返しの回（完了 / スキップ / 未処理）、Sprint 中の追加、Today での見送り・今日はここまで、割り込み。
- Goal と可用時間を Sprint 中に変えていれば、計画時との差を出す。
- Planning で外した繰り返しの回は出さない。
- 気になった事実に「気になる」の印を付けると、右側の振り返りの材料に集まる。印を付けなくても次へ進める。

### 振り返る

- 入力は基本的に 2 つ：「気になったこと」（任意）と「次の Sprint で 1 つだけ変えてみること」。長い KPT や持ち越しの理由を求めない。
- 事実（`body`）と本人の振り返り（`reflection`）を分ける。Agent は事実を根拠に問いや文案を出してよいが、原因を本人の代わりに断定しない（Agent の見立ては破線、本人が加えるまで `body`）。

### 引き継ぐ

- 改善策を 1 件、自然文で確定する（下書き →「改善策として確定」）。次の Planning の最初（選ぶ段階の右ペインの上部）に表示だけで戻る。
- 改善策が機械的に適用できる場合だけ、任意で計画基準を作れる（MVP は「Estimate の幅を下限 / 中央 / 上限のどこで計画値に使うか」と対象の Area だけ）。
- Active な計画基準があった Sprint では、使った / 使わなかったにかかわらず「続ける / 終える / 置き換える」を選ぶ。理由は求めない。選ぶまで Retro は完了しない。次回に有効な基準は最大 1 件。
- 基準の設定、効果の説明、次回 Planning のプレビューは同じ値から作り、食い違わせない。
- Retro を完了すると Sprint は閉じ、次の Sprint を確定できるようになる。途中で閉じても書いた内容は残る（ヘッダーに「書いた内容は、途中で閉じても残ります」）。

### ルール

- 失敗の言葉を使わない。数値の比較は「計画 27h → 実績 24.5h（入力済み 11件）」の形。割合や点数で評価しない。
- Retro は数分で終えられる量にする。
