## 共通

- 画面ごとに「決めていること」を 1 つだけ見出し（`display-m`）にする（Planning：「今週、何を進めるか」→「今週、どんな状態にしたいか」→「この計画で、進められそうか」、Retro：「Sprint 14 で何が起きたか」）。見出しの「今週」は、開いている Sprint の呼び名に従う（下の「どの Sprint も開く」）。
- Sprint の画面（Planning / Today / Retro）の Area 名は Sprint 確定時の名前で固定し、Backlog は現在の名前を出す（ドメインモデル F5）。確定前の Planning は現在の名前。
- 容量の超過は Planning だけで扱う。Today と Backlog では超過を表示しない（不変条件 25）。
- 画面を移ったら、移った先を先頭から表示する（Issue #111）。同じ画面の中で段階（`stage`。Planning も Retro も）を替えたときも同じ。フィルター・Task を開く・Sprint や日の切り替えなど、ほかの検索パラメータの変更ではスクロールを動かさない。ブラウザの戻る・進むでは、その履歴の位置に戻す。
- 持ち越し・見送り・超過・「できなかった」は事実として中立に書き、人格評価のように見せない。

### 大きい画面（1920px 以上、Issue #81）

Issue #81 でオーナーが決めた（2026-09-29）。DESIGN.md の Layout（`bp-xl`、`pane-rows`）が正。

- 画面の大きさで変えてよいのは、ペインの広さと、その中に並ぶ数だけ。どのペインに何があるかは変えない。中央のペインは、左右のペインを除いた幅を使い、上限は中身の種類で決める（ブロックは列を増やす、表は幅いっぱい、1 行 1 Task の一覧は最大 1280px、文章は `measure-read`）。
- Planning：Sprint ペインを広げ、Area のブロックを幅に応じて 1〜3 列に並べる（列は 26rem 以上、3 列まで）。1 列のときは今どおり最大 680px。左の Backlog ペインは `pane-list-xl`（480px、整える・確かめるは `pane-list-slim-xl` 320px）に広げる。時間の見通しの幅は今のまま。1920px 未満は、中央のペインに余りがないので広げない（1440px で中央は約 450px。Issue #158）。
- Backlog：一覧の行は最大 1280px で止め、左に置く。詳細の Drawer は今と同じ（右に重ねる）。絞り込みと Quick Add も同じ幅で止める。
- Retro：3 段階とも本文を左に揃える（段階を切り替えても左端が動かない）。事実を見るの表は幅いっぱい（列は割合で分け、タイトルが幅を取りすぎない）。繰り返しの回は最大 1280px。文は 720px、振り返る・引き継ぐの材料は 336px のまま。

### どの Sprint も開く（Issue #90）

Issue #90 でオーナーが決めた（2026-09-30）。週の呼び名の規則は、決定から実装で定めた（オーナーの確認は PR で取る）。

- Sprint と振り返りの画面は、どの Sprint も開ける。開く Sprint は URL の検索パラメータ（`?sprint=3`）で持ち、アプリ全体のストアには持たない（ADR 0005）。ナビの「Sprint」「振り返り」は今の Sprint を開き、前に選んだ Sprint を持ち越さない。今の Sprint は、Sprint の画面では実行中、なければ計画中、なければ振り返り中の Sprint。振り返りの画面では振り返り中、なければ実行中、なければ最後に完了した Sprint。
- Sprint Header のタイトルの左右に、前後の Sprint へ移る矢印を置く（DESIGN.md Sprint Header）。Sprint の画面では、最後の Sprint の次に「次の週」がある。計画中の Sprint があるときは次の週はない（計画中の Sprint は 1 つだけ）。
- 次の週（計画を始める前）は、Sprint Header（Status なし）に「Sprint N の計画を始める」（Primary）を置き、見出し「来週の計画はまだありません」と、確定できる条件を出す：前の Sprint の Retro を完了してから確定できること、前の Sprint が実行中ならその Retro を始められる日（最終日、F21）、振り返り中なら振り返りへのリンク。実行中の Sprint の画面には「Sprint N の計画を始める」を置かない。
- 振り返り中と完了の Sprint の Sprint の画面は、確定したときの計画と結果を読み取り専用で出す：見出し「Sprint N の計画と結果」、Area ごとの Goal（確定時の Area 名、F5）と Task（計画の時間、完了・「持ち越し（未完了）」）、計画の合計と使える時間、計画のルールの扱い。目標と使える時間は変えられず、日ごとの記録は出さない。右上に、振り返り中は「振り返りを開く」（Primary）、完了は「振り返りを見る」（Secondary）。
- 完了した Sprint の振り返りは、3 段階を読み取り専用で出す（事実と Goal の自己判定、気づいたことと次に試すこと、計画のルールの決定）。入力欄・「振り返りに使う」・自己判定の RadioGroup・「かかった時間を記録」は出さない（F22、不変条件 40）。自己判定は Tag で、未判定なら「自分の評価：まだ」と出す。ヘッダーの下に「完了した後は、書いた内容を変えられません。」（変えられる場所はないので、行き先は書かない。Issue #168）。段階表示は、3 段階とも済んでいるので「現在」と黄の印を出さず、開いている段階は太字だけにする（`aria-current="page"`）。引き継ぐの末尾（「振り返りを完了」があった場所）に「Sprint N の計画を始める」（Primary）を置き、Sprint Header の同じボタンは、そのとき Secondary にする（画面の Primary は 1 つ）。事実を見る・振り返るでは Sprint Header のボタンが Primary。Planning がすでに始まっていれば、同じ形のボタンで「Sprint N の計画を開く」にする。
- 振り返りの画面で、実行中の Sprint は「この Sprint の振り返りは、最終日の M/D (曜) から始められます。」（最終日は「振り返りを始める」）、計画中の Sprint は確定した後の最終日から始められることを出す。

#### 週の呼び名

- 実行中の Sprint があるあいだは、それを「今週」、その次の Sprint（計画中、または次の週）を「来週」と呼ぶ。
- 実行中の Sprint がない（前の Sprint が振り返り中か完了）ときは、次に始まる Sprint（計画中、または次の週）を「今週」と呼ぶ。日曜の夜に翌週を計画する、ふだんの場合の語を変えないため。
- 「今週」の前の週の Sprint は「先週」と呼ぶ（Issue #168。オーナーの確認は PR で取る）。振り返り中の Sprint は、次に始まる Sprint が「今週」になるので、いつも「先週」になる。「先週」は Sprint Header の期間の前に添えるだけで、見出しと案内文は「Sprint N」のままにする。
- どれにも当たらない Sprint は「Sprint N」と呼ぶ（それより前の Sprint）。
- Sprint Header は、呼び名があれば期間の前に太字で添える（「来週 · 10/5 (月) – 10/11 (日)」）。見出し、案内文、Toast、□ とグループの Checkbox の読み上げ、行とグループの語（「今週の繰り返し」「今週から外す」「今週 N回」、確定できない理由）は、開いている Sprint の呼び名に従う（「来週、何を進めるか」「3件を来週に入れました」「来週に入れる：タスク名」）。Backlog の「今週」の印は、Sprint に依らない画面なので今までどおり（実行中の Sprint、なければ計画中の Sprint）。

### リストのキー操作（Issue #48 の実装で決めたこと。オーナーの確認は PR で取る）

キーの割り当ては [accessibility.md](accessibility.md) の「キーボード」が正。ここには、表から読めない振る舞いを書く。

- 「行にフォーカスがある」は、行のタイトル（行全体で詳細を開くボタン）にフォーカスがあるとき。Space はそこで行のコントロール（○・□・「今日へ」）を押し、詳細は開かない。コントロール自身や `…` にフォーカスがあるときは、それぞれのボタンの操作になる。押せるコントロールのない行（スキップした回、Backlog の繰り返しの Task）では何もしない。コントロールを持たない行（Planning の今週の側と、Backlog のペインの「今週の繰り返し」。後者は回ごとの Checkbox だけを持つ）では、Space も Enter と同じく詳細を開く。
- E と Delete は、行の中のどこにフォーカスがあっても効く。E は Task の詳細を開き、Estimate の欄にフォーカスを置く（Backlog・Today・Planning の両方のペイン）。詳細を開けない行（Today の完了した Task、Planning で完了・アーカイブした Task）では効かない。
- 見積もりを入れる入口は E のほかに 2 つ（Issue #96。オーナーの確認は PR で取る）。どちらも E と同じ結果になる（詳細を開き、Estimate の欄にフォーカスを置く）。
  - 行の `…` の「見積もりを入れる」（右端に Kbd の E）。`…` を持つ行（Backlog、Today の今日やる、Planning の今週の側と Backlog ペインの行）に出す。詳細を開けない行（Today の完了した Task、Planning で完了・アーカイブした Task）と、`…` のない行（Today の昨日の続き・今週の残り。詳細は行を開いて入る）には出さない。Planning の Backlog ペインを細くしている間（整える・確かめる）は行にタイトルだけを出すので、`…` も出さない（E は効く）。
  - Planning の今週の側の行で、見積もりのない Task の「見積もりなし」は押せる（読み上げは「見積もりを入れる：タスク名」）。完了・アーカイブした Task の行、ほかの行、計画の時間や提案は押せない（直すのは詳細の Estimate。不変条件 7）。
- Delete は Mac の delete キー（Backspace）でも効く。アーカイブしたら、フォーカスは次の行へ移す（なければ前の行、それもなければクイック追加）。`…` のアーカイブも同じ。
- Alt+↑↓ の並べ替えは作っていない。今は並べ替えを持つリストがない（Backlog は新しい順、不変条件 5）。
- Planning の ⌘/Ctrl+Enter は 1 文字ではないので、入力欄の中でも効く。確定できないときは Dialog を開かず、確定ボタンへフォーカスを移して、理由を読み上げさせる。N は、compact の「整える」「確かめる」（Backlog のペインがない）では何もしない。
- どのキーも、Drawer・Dialog・Menu の中では効かない（そちらのキー操作が優先）。1 文字のキーと Delete は、入力欄の中と、日本語の変換中は効かない。

- **Browse**：Area の Filter と、絞り込み「すべて / 期限が近い / 期限切れ / 持ち越し / 繰り返し / 領域なし」。優先度だけで既定の並び順を決めない（並びは新しい順。作った日時の降順で、優先度ではない）。行には優先度の高・低だけを Task Metadata に語で出す（「優先度 高」。通常は出さない。色で強調しない。並びは変えない。Issue #97）。今の Sprint に入っている Task には「今週」と出す。繰り返し Task は Rule ごとに 1 行（「毎週 土 · 次は 10/3 (土)」）で、未来の回を並べない。繰り返しをやめた Task は、最後の日まで「毎週 土 · 次は 10/3 (土) · 10/4 (日) まで」と出して絞り込みの「繰り返し」に残し、最後の日を過ぎたら単発の行（○）になる（F41、Issue #189）。完了は回ごとなので、行の ○ の位置に ↻ を置く（押せない。読み上げは「1回ずつ完了」。Issue #171）。サブタスクのある Task の行には「サブタスク 1件 · （参考）1h」を Task Metadata に注記（`ink-subtle`、アイコンなし）として出す。計画の時間がサブタスクの合計のときは「サブタスクの合計」と出し、右端の Estimate がその合計になる（不変条件 10。Issue #171）。
- **領域を編集**：領域の Filter の並びの端に「領域を編集」（Quiet の Button）を置く。領域がまだなくても出す。Task の詳細と追加欄（Backlog・Planning・Today）の領域の Select の末尾には「新しい領域…」を置く。どちらからも同じ Dialog「領域を編集」を開き、領域を作る・名前を変える・アーカイブする。Issue #113 でオーナーが決めた（2026-09-30、決定シート R12=A）。
  - Dialog には、アーカイブしていない領域を並び順に、路線記号と名前で並べる。各行の右端に Quiet の「編集」を 1 つ置く（行ごとにアーカイブのボタンを並べない）。下に「新しい領域」の欄と「追加」。フッターは「閉じる」だけ。中身がその場で変わるので、Dialog は上下中央ではなく上端に寄せ、行を開いてもタイトルと行の位置が動かないようにする。
  - 作る：Enter か「追加」で作り、欄を空にして続けて作れる。空のままでは何もしない。「新しい領域…」から開いたときは、欄にフォーカスを置き、作ったら Dialog を閉じて、その領域を Select で選んだ状態に戻す（Task の詳細なら、その Task の領域として保存する）。閉じるだけなら Select は変えない。
  - 編集：行がその場で開き、名前の欄（「確定済みの Sprint では、前の名前のままです。」と添える。F5）、「アーカイブ」（Secondary、左端。元に戻せるので danger にしない。Issue #164）、「キャンセル」「名前を変える」（右端）を出す。Enter か「名前を変える」で保存し、Esc か「キャンセル」で行に戻す（Esc で Dialog は閉じない）。空の名前は保存せず、欄の下にエラーを出す。Backlog の Filter・Select・行はすぐ新しい名前になる。
  - アーカイブ：確認を挟まない。行の位置に「「名前」をアーカイブしました。Task と過去の記録には残ります。」と「元に戻す」を残す（Dialog を閉じるまで）。アーカイブした領域は Filter と Select の候補から消え、その領域の Task の行と詳細には名前が残る。その領域で絞り込んでいたら、その絞り込みは効かなくなる（外す Filter がないため）。追加欄でその領域を選んでいたら「領域なし」に戻る。
  - 色は作った順に `area-1` から割り当て、8 個目からは `area-1` に戻って繰り返す（DESIGN.md「Area の路線記号」）。色の変更と並べ替えは MVP では扱わない。
- **Organize**：行を開くと、desktop は一覧を見失わない右 Drawer、compact は Bottom Sheet。タイトル、説明、Area、期限、優先度、Estimate、繰り返し、Subtask、アーカイブを編集する。Backlog・Planning・Today で同じ詳細を使う。Issue #95 でオーナーが決めた（2026-09-30）。
  - 保存はすべて即時。文字を入れる欄は欄を離れたとき（Enter でも）、選ぶ欄は選んだときに保存し、値が変わっていなければ記録しない。保存したことは、欄のラベルの行の右に「✓ 保存しました」と控えめに示す（Toast は使わない）。不正な値（空のタイトル、0 以下の Estimate、日付でない期限）は、欄を離れたときに欄の下にエラーを出し、保存せず、入力も消さない。Subtask の追加は、今どおりボタン（「追加」）で記録する。繰り返しは、ルールができている Task では、ほかの欄と同じく選んだ時点で保存する：頻度、毎週の曜日（チェックのたび。曜日が 1 つもないあいだは保存せず、外して 0 にしたときは欄の下にエラーを出す）、毎月の日。ボタンは置かない。繰り返しにする最初の 1 回だけは、今どおりボタン「繰り返しにする」で記録する（選び間違い・キーボードで Select を通っただけで繰り返しにならないため。Rule を作ると行の ○ が ↻ になる）。次の Sprint から別のルールになるときは、入力の下に「次の Sprint から：毎週 月・火・水・金」を全文で 1 行出す（見出しの下の行は長いと切れるため。入力の下なら増えても押している欄が動かない）。保存したあとは、節の見出しの右に「✓ 次の Sprint から反映 · 日付」を出す（ほかの欄の「保存しました」と同じ位置の考え方。下の欄を押している指の下が動かない。Issue #171、2026-10-01）。ルールがあるあいだは、節の末尾（「繰り返しにする」と同じ位置）にボタン「繰り返しをやめる」（Secondary。danger にしない）を置く。押すと、節の見出しの右に「✓ 繰り返しをやめました」を出す。やめたルールは、最後の日まで入力とボタンを出さず「今の設定：毎週 土 · 10/4 (日) まで」の 1 行だけを残し、フォーカスを節の見出しへ移す。回を 1 つも作っていないルールは外れ、欄は「繰り返しにする」の状態（既定の選択）に戻り、フォーカスは頻度へ移り、行の ○ が戻る。確認も「元に戻す」も挟まない（F41、Issue #189、2026-10-01）。
  - フッターは「閉じる」だけ。閉じる・×・Esc・別の行を開く、のどれでも、入力中の欄は離れたときと同じ規則で保存する。不正な値が残っていれば閉じずに（別の行も開かずに）、その欄にフォーカスを戻す。
  - 入力中の Subtask（タイトルか Estimate に文字がある）か、保存していない繰り返しの選択（ルールがない Task で、既定の毎週・曜日なしから変えたのにまだ「繰り返しにする」を押していない。ルールがある Task で、毎週の曜日が 0 のまま）があるときは、閉じる・×・Esc・別の行を開く、のどれでも閉じず、切り替えない。代わりに Drawer の中（フッターの上）に Notice で「入力中のサブタスクがあります」と、繰り返しは、ルールがない Task なら「「繰り返しにする」をまだ押していません」、ルールがある Task なら「繰り返しの変更がまだ保存されていません」と、「戻る」「保存せずに閉じる」（別の行を開こうとしたときは「保存せずに開く」）を出し、フォーカスを「戻る」に置く。「戻る」はその入力へフォーカスを戻し（「詳しく」の中なら開く）、「保存せずに閉じる」「保存せずに開く」は入力を捨てて、閉じるか別の行を開く。画面全体を覆う Dialog は使わない。入力がなければすぐ閉じる。Issue #88 の対応として決めた（2026-10-01）。
  - 開いたときのフォーカスは見出し（Task のタイトル）に置き、どの欄にも入れない（compact で開いただけではキーボードが出ない）。E で開いたときだけ Estimate の欄に置く。
  - 並びは上から、今日と今週（今日へ・今日の操作・完了にする。繰り返しの Task は「今週の分を開く」で Today へ）→ タイトル・Area・期限・優先度・Estimate（Estimate の提案はその下）→ 説明・Subtask・計画の時間・繰り返し → アーカイブ。優先度は「詳しく」に畳まず、スクロールなしで届く位置に置く（Issue #171）。3 つめのうち、開いたときに値のある項目（説明がある、Subtask がある、繰り返しの Rule がある）は開いた状態で出し、値のない項目は「詳しく」に畳む。「詳しく」の横に、畳んだ項目の名前を並べる。
  - 「計画の時間」は Subtask の一覧の直下に置き、どちらの選択肢にも値を出す（「このタスクの見積もり 6h」「サブタスクの合計 2h（1件は見積もりなし）」。見積もりがなければ、「見積もり」が続かないようにこの選択肢の中だけ「なし」。「サブタスク」も続かないように、件数は「1件は見積もりなし」。Issue #162）。説明は「タスクの見積もりとサブタスクの合計は、どちらか一方を計画に使います。」。選んだ側だけが Planning の合計に入る（不変条件 10）。
  - Estimate の提案があれば Agent 提案（見出し「見積もりの提案」）で出し、下限・中央・上限のどれかを採用する（「上限 4h を使う」）か、値を直して採用（「直して使う」）できる。使う・直して使う・使わないの後は 1 行と「元に戻す」を残す（agent-ui.md）。繰り返しの Rule を変えたら「次の Sprint から反映」と書く。
- **今日へ**：Sprint 外の Task を「今日へ」入れると、1 操作で今の Sprint に Sprint 中の追加として入り、今日の選択にもなる。確認 Dialog も容量の警告も出さない。Issue #94 でオーナーが決めた（2026-09-30）。
  - 入口は、行の `…` と Task の詳細の先頭（「今日と今週」）。行には「今日へ」のボタンを出さない。`…` は medium 以上でも常に見せる（hover の裏に置かない。Issue #164）。
  - 入れたら Toast「「タイトル」を「今日やる」に入れました」に「今週にも入りました。」を添え、操作は「今日を開く」（Today へ移る）。「元に戻す」は添えない（取り消すと、Sprint 中の追加と今日の選択を記録ごと消すことになり、ドメインモデルの決定が要る）。同じ種類の Toast は最新の 1 つに置き換わる。
  - 詳細では、押したあとボタンの代わりに「「今日やる」に入っています」と「今日を開く」を残し、フォーカスは「今日を開く」に置く。「今日やる」に入っている Task の詳細には、今日の状態に合わせて日次の操作（開始、今日はここまで、今日は見送る、今日の予定から外す、繰り返しの回は今日はスキップ）も出す。Today の行の `…` と同じ操作で、同じ記録になる。「今日はここまで」は、Drawer の中に別の面を重ねないので、節の中に任意の「かかった時間」の欄を開き（Enter か「今日はここまで」で記録、Esc か「キャンセル」で閉じる）、行の面と同じ記録を残す。今日はここまで・見送り・外したあとは、節に「今日はここまでにしました。明日から今週の残りに出ます。」「今日は見送りました。明日から今週の残りに出ます。」「今日の予定から外しました。」を残す。Today の画面で開いた詳細には「今日を開く」を出さない。
  - 行の語は、「今日やる」に入っていれば「今日」、今週の Sprint にあって「今日やる」にないものは「今週」（「今日やる」に入っていれば今週の Sprint にも必ずある。不変条件 26）。「週の途中で追加」はどちらにも続ける。今日はここまで・見送り・外したものは今週の残りに戻るので「今週」に戻る。実行中の Sprint があるあいだに来週の計画（下書き）へ入れた Task には、最後に「来週」を足す（「今週 · 来週」「今日 · 来週」。来週だけなら「来週」）。来週から外せば消える。繰り返しの Task は計画を始めると来週に入るので、選ばなくても出る。詳細の見出しの下も同じ語。Backlog の切り口に「来週」は足さない。
- **今週へ**：Sprint 外の単発の Task を、今日を選ばずに実行中の Sprint へ Sprint 中の追加として入れる（ドメインモデル F40）。確認 Dialog も容量の警告も出さない。Issue #155 でオーナーが決めた（2026-10-01）。
  - 入口は、行の `…`（「今日へ」の次）と Task の詳細の「今日と今週」（Backlog・今日の画面で開いたもの。Planning で開いた詳細には出さない）。出すのは、実行中の Sprint（開始日の前でもよい。今日を選ばないので）があり、その Task がまだ入っていないときだけ。繰り返しの Task には出さない。語は週の呼び名に従う（実行中の Sprint は「今週」）。
  - 入れたら Toast「「タイトル」を今週に入れました」と「元に戻す」。元に戻すと、追加を記録ごと消し、行の「今週」が消えて「今週へ」「今日へ」がまた出る。「今日やる」に入れた後は元に戻せない（F40）。
  - 詳細では、押したあと「今週へ」と「今日へ」が消え、フォーカスは残ったボタン（「完了にする」）に移る。「今日やる」には、今日の画面の今週の残りから入れる。
- **完了**：今の Sprint の Task を Backlog から完了すると、その Sprint と今日の完了にも反映する（Today の「済んだもの」に出る）。完了した行は一覧から消え、その位置に「「タイトル」を完了にしました」の 1 行と「元に戻す」ボタンを残す（Toast にはしない。ほかの操作をするか画面を離れると消える）。元に戻すと完了前の状態に戻る（ドメインモデル F29）。

## Sprint Planning

最重要の体験。1 つの workspace が **選ぶ（Pick）→ 整える（Shape）→ 確かめる（Check）** と自然に変化する。強制のウィザードにせず、どの段階にも戻れる。

### 画面構成（wide）

| 領域 | 密度 | 中身 |
| --- | --- | --- |
| Sprint Header | — | Status「計画中 · 未確定」（draft の破線 Tag）、タイトル（`display-l`）、期間、段階表示（路線図の形。現在の段階は黄の印。compact では 1 行に収め、折れるときも駅を結ぶ線は前の駅の後ろに付いて、行の先頭に残さない。Issue #166）、操作（変更履歴 / Agent に計画案を依頼 / 「Sprint を確定」= 唯一の Primary） |
| Backlog（左、`canvas-subtle`） | Task density | Task Quick Add、Filter、グループ（持ち越し → 期限切れ → 期限が近い → 今週の繰り返し → その他）、□ で今週へ選ぶ |
| Sprint（中央、`canvas`、最大 680px） | Thinking space | 段階ごとの見出し（`display-m`）、Area ごとの Goal と選んだ Task |
| 時間の見通し（右） | Thinking space（狭い） | 前回、次に試すと決めたことと有効な計画のルール（選ぶ・整えるは名前の 1 行。確かめるは枠を中央の要約に置き、右には出さない）、使える時間と Capacity（確かめるはバーと内訳だけ）、Agent 提案。compact・medium の Drawer は見出し「時間の見通し」を 1 回だけ出し、中身は見出しを重ねず、使える時間の欄を上に寄せる（Issue #166）。Backlog をスクロールしても画面に残す（sticky。右だけが画面より長いときは右の中でスクロールする。Issue #165） |

### 選ぶ（Pick）

- Backlog、持ち越し、期限、今週の繰り返しを眺め、□ で今週へ選ぶ。選ぶと行が `here-subtle` とチェックになり、中央の該当する Area に現れる。Toast「〜を今週に入れました · 元に戻す」。実行中の Sprint があるあいだに次の Sprint を計画するときは、この段落の「今週」がすべて「来週」になる（上の「週の呼び名」）。
- 今週の繰り返しの回は、既定で選択済み。不要な回は外せる（外した回は Today にも Retro の事実にも出ない）。
- 持ち越しは自動で入らない。「持ち越し」グループの候補として出し、本人が選ぶ。
- 実行中の Sprint の週に次の Sprint を計画するとき、実行中の Sprint にまだ完了していない Task は、候補の行に「Sprint N で進行中」と出す。選ぶことは止めない。選んでおいた Task は、実行中の Sprint が振り返りに入るときに持ち越しとしてつながり、「持ち越し N回」は選んだ後も消えない（Issue #89、ドメインモデル F35・F36）。
- その場でタスクを追加・編集できる（Planning を中断しない）。追加したタスクは選択済みで入る。Estimate は「見積もりなし」で入り、Capacity に「見積もりのないタスク 1件は合計に含まれていません。」。
  - 追加欄の名前とプレースホルダーは「今週のタスクを追加」（週の呼び名に従う。細い Backlog に収まる長さにした）。入力を 1 行目に置き、2 行目に領域の Select（Backlog・今日の画面と同じ `AreaSelect`。選んだ領域の路線記号が出る）と「追加」ボタンを並べる（Issue #98。選ぶでも 整える・確かめる（240px）でも同じ）。既定は領域なしで、選んだ領域は次の追加にも残る。
  - 追加すると Toast「「タイトル」を追加して今週に入れました」が出る（「今週」は上の「週の呼び名」に従い、次の Sprint の計画では「来週」）。「元に戻す」は添えない（外すときは中央の行の `…` の「今週から外す」）。
  - 中央の、選んだ領域（選ばなければ「領域なし」）の塊に新しい行が出て、Backlog の Capture と同じ `here-subtle` の点滅で 2.5 秒かけて消える。中央の行は地を塗らないので点滅が見える。`prefers-reduced-motion` では動かさず、Toast が知らせる。768px 以上で行が画面の外にあるときは、追加欄を画面の外に出さない範囲で、行が見えるところまでスクロールする（768px 未満は追加欄の位置を保ち、Toast が知らせる）。
- 選ぶ段階の見出しの下に、選んだ件数にかかわらず案内を出す。今週の繰り返しがあるときは、最初から入っていることと、外すと今日の画面にも出ないこと。あわせて、Backlog でチェックしたタスクが、ここに領域ごとに並ぶこと。行の見た目の変化は文で説明しない（Issue #92、#208）。
- Goal の入力をこの段階で求めない。前回、次に試すと決めたこと（表示だけ）を右ペインの上部に出し、有効な計画のルールがあれば、その下に名前だけを 1 行で出す（「研究：見積もりの提案の上限で計画する」。枠・Switch・効果は出さない）。計画のルールがなければ何も出さない（Issue #105 のオーナー決定 R3）。選んだ Task にルールが効くもの（幅のある計画値で、ルールの対象の Area）が 1 件もないときも出さない。Task を選ぶと出る（Issue #161）。
- Capacity は主役にしない。選んだ Task の合計と使える時間をヘッダーに控えめに出す。
- 使える時間の入力欄は、Capacity の計画の合計の直下に置き、1280×800 でも最初の画面に入れる（Issue #165）。
- Planning で Task の詳細（右 Drawer）を開いている間は、右の時間の見通しが隠れるので、詳細の「閉じる」の横に compact と同じ 1 行（「時間の見通し 残り 1 〜 3h · 収まる」）を `role="status"` で出す。見積もりを入れた結果が閉じる前に分かる（Issue #165）。
- 一括選択はグループ見出しの Checkbox（indeterminate あり）。解除は中央の行メニュー「今週から外す」でもでき、どちらも元に戻せる。
- Backlog が空の初回は、クイック追加を大きく（`control-lg`）表示して始める。

### 整える（Shape）

- Area ごとに Goal と選んだ Task を同時に見ながら編集する。左に Backlog を細く残し、行き来できるようにする。
- Goal は **Area ごとに任意**。全体 Goal の入力欄は作らない。Task があって Goal のない Area は「+ 目標を書く」だけ。目標が任意であることを文で添えない（領域ごとにくり返すため。Issue #208）。Goal も Task もない Area は、名前と「+ 目標を書く」だけの 1 行にする（先に Goal だけ書けるまま、空の欄を大きく残さない。Issue #161）。計画のルールは、選ぶと同じく名前の 1 行だけにする。選んだ Task にルールが効くものがなければ、この 1 行も出さない（Issue #161）。
- 編集は `body-l` の Textarea（ラベル「目標（今週の終わりにどんな状態にしたいか）」、help は「〜な状態にする」の形の推奨）。保存すると `goal` で組み直す。
- Task は「目標に入っている / 入っていない」を選べる。Planning で選んだ繰り返しでない Task の既定は「入っている」、繰り返しと Sprint 中の追加は「入っていない」。確定時に Goal のない Area の Task は「入っていない」になる。目標に入っていない Task も時間の合計に含め、薄くしたり除外を促したりしない。
  - 目標に入っているかは Goal のある Area の行にだけ出す（整える・確かめる）。行のメタデータに「目標に入っている」（`target`）か「目標に入っていない」を同じ調子で出し、行の `…` には逆の操作「目標から外す」「目標に入れる」を出す。Goal のない Area と領域なしの行には、状態もメニューも出さない（確定すると目標に入らないので、選ばせない。Issue #159）。
  - 目標に入っているかは行の印と `…` の操作だけで伝え、整えるの案内文や、繰り返しが目標に入らない理由の文は添えない（状態や仕組みを言い直す説明文を足さない。Issue #159 のオーナー決定）。
- Goal を書いた後に Task を増減してよい。Agent の Goal 文案は Goal の直下に Agent 提案で出す（採用しても `body-l` → 保存で `goal`）。

### 確かめる（Check）

- 見出し「この計画で、進められそうか」。中央の見出しの直下に、確定の Dialog と同じ材料の要約を置き、最初の画面で計画が収まるかが分かるようにする。値は Dialog と同じ関数から出す。その下に、Area ごとの Goal・Task・計画の時間を読むために並べる。右は Capacity（Issue #93 のオーナー決定 S4、2026-09-30）。数字は中央の要約にだけ出し、右は前回、次に試すと決めたことと、Capacity のバーと Area ごとの内訳だけにする（同じ数字を画面に 2 回出さない。Issue #165）。
- 要約（見出しは「まとめ」）は上から、計画が収まるかの文（状態のアイコンと語）、計画の合計・タスクの件数（うち目標に入っていない件数。Goal のある Area の、行に「目標に入っていない」と出る Task だけを数え、Goal のない Area の Task は数えない。Issue #159 のオーナー決定）、見積もりのない件数の文、使える時間の入力欄、「何が上振れすると超過するか」、見積もりのないタスク（行ごとに「見積もる」で Estimate を開く。サブタスクだけが見積もりなしなら詳細を開く）、目標のない領域（「「整える」で書く」で整えるへ移る）、計画のルールの枠（ルールが効く Task があるときだけ）。
- 要約の下の Area の塊には「+ 目標を書く」「編集」と、目標が任意だという案内を出さない。目標は「整える」で書く。Task の行は、ほかの段階と同じく開けて、`…` から外せる。
- 使える時間は本人が入力する。確かめるでは要約の入力欄だけで入れ・変え、右の Capacity には入力欄を出さない（同じ欄を 2 つ並べない）。未入力なら、要約に「使える時間を入力すると、計画との差を表示します。」
- 計画の合計は幅のまま（「16.5–18.5h」）、残りは「残り 1 〜 3h」。差が 0 をまたぐときは「少なく済めば 2.25h 残る · 多くかかれば 0.75h 超える」の 2 つの文にする（Issue #93 のオーナー決定 S5、Issue #162）。このとき状態の文は「超える可能性」だけにして数字を繰り返さず、要約と確定の Dialog の状態の行は「超える可能性：少なく済めば 2.25h 残る · 多くかかれば 0.75h 超える」にする（同じ数字を言い直す「計画値が下限どおりなら、残り 〜 です。」も出さない）。下限でも超えるときも同じく、状態の文は「少なく済んでも超える」、要約と確定の Dialog の状態の行は「少なく済んでも超える：超過 3 〜 5h」にする（Issue #165）。状態は ok / tight / over / unknown（DESIGN.md Capacity Indicator）。内訳は Area ごと。
- 幅がある場合は「何が上振れすると超過するか」を書く（例：「計画のルールで「関連論文を 3 本読む」を 5h で計算しています（見積もりの提案 3–5h）。」超過の量は状態の行にあるので、ここでは繰り返さない。Issue #165）。調整案は「調整案を見る」で開く段階表示にし、強制しない。
- 有効な計画のルールがあれば、この段階で初めて枠（`canvas-subtle`）で出す。枠は中央の要約の最後に置き、右には出さない（同じことを 2 か所に出さない。Issue #165）。ラベル「計画のルール」、名前、「このルールで計画する」Switch、効果（「研究のタスク 1件を、見積もりの提案の上限で計画しています（合計の下限 +2h）。」）。計画のルールがなければ何も出さない（Issue #105 のオーナー決定 R3）。選んだ Task にルールが効くものが 1 件もないときも、枠ごと出さない（「対象はありません」の文も出さない。Issue #161）。
- 超過していても確定できる。止めずに、確定の Dialog で再提示する。

### Agent の計画案

- 「Agent に計画案を依頼」または外部 Agent から届いた計画案は、ヘッダーの 1 行「Agent 提案 · 外部 Agent の計画案が 1件あります · 現在の計画との差分を見る」（UI v0.1 モック）と、右ペインの Agent 提案（要約＋「差分を確認」）で知らせる。ヘッダーの表示は破線の小さな「Agent 提案」の印と `ink-muted` の文字にし、「現在の計画との差分を見る」だけをリンクにする。目立たせない（PRD §12）。
- 「差分を確認」で右 Drawer（compact は全画面）に計画案の差分。行ごとに選び「選んだ N件を計画に反映」。反映しても Sprint は確定しない。Capacity は反映後の値で出す。
- 計画案の作成後に Backlog が変わったら、Notice（info）「計画案の作成後に Backlog が変わりました。差分を再確認してください」。

### 実行中の Sprint（Issue #51 の実装で決めたこと。オーナーの確認は PR で取る）

- Sprint の画面は、ナビから開くと実行中の Sprint を出す（次の Sprint を計画中でも。Issue #90）。Sprint Header は Status「進行中」（実線の Tag）、タイトルと前後の矢印、「今週」と期間と「N日目 / 7日」で、段階表示はない。右に「今日を開く」（Primary。開始日より前は出さない。Issue #156）。次の Sprint の計画は、→ で開く次の週から始める（Issue #90 で「Sprint N の計画を始める」をここから外した）。
- 実行中の Sprint を開いているときだけ、Sprint Header の下に Progress「今週の完了 N / M件」を出す（Today の上部と同じ数。繰り返しは回で数える、ドメインモデル F32）。件数だけで、残り時間は出さず、超過や不足を示す色・語も使わない（Issue #103、オーナー決定 B14=A）。振り返り中・完了した Sprint には出さない（結果は Retro の事実で見る）。
- 見出しは「今週の計画」。Area ごとに Goal（確定時の Area 名、F5）と選んだ Task を並べる。Goal のない Area には「+ 目標を書く」だけを出す（目標は任意という案内は、計画中の画面にも置かない。Issue #155・#208）。Task の値は確定したときの計画の時間（planSnapshot、繰り返しは今週の回の分）。持ち越してきた印・完了・今週の回の進み・週の途中で追加・目標に入っている / 入っていない（Goal のある Area だけ。Planning の行と同じ語と調子。Issue #159）をメタデータに出す。実行中の Sprint では、来週の計画にも入っている Task の行に最後の語として「来週にも」を出す（来週から外せば消える。終わった Sprint には出さない）。
- 前の Sprint から持ち越してきた Task は、Backlog と同じ CarryOverIndicator（「持ち越し 1回（Sprint 13から）」、DESIGN.md）を、結果（「完了」）より前に置く。どこから来たかを結果と取り違えないため（Issue #160）。
- 繰り返しの行は、今週の回の進みを「今週 3回中 1回完了」と出す。数え方は「今週の完了」と同じ（F32）で、行の数を足すと上の件数になる。スキップした回は数から外れるので「· スキップ 1回」と添える。振り返り中・完了の Sprint では「今週」を付けない。行に結果の「完了」が出ているときは、回の進みに「完了」を重ねない（「3回中 3回」。Issue #160）。
- 実行中の Sprint では、行のタイトルから Task の詳細（Backlog・Today と同じ Drawer）を開ける。詳細で変わるのは Task だけで、この画面の計画の時間（planSnapshot）は変わらない。完了・アーカイブした Task と、振り返り中・完了の Sprint の行は開かない（Issue #160）。
- Goal は確定後も文を変えられ、新しく書ける。消すことはできず、空で保存すると理由を出して入力欄にフォーカスを戻す（F16）。確定したときの文と違えば「確定したとき：「…」」、確定後に書いた Goal には「確定した後に書いた目標です」を添える（不変条件 18、MVP 完了条件 16）。
- 使える時間は確定後も変えられる。計画の合計と「確定したときの使える時間」を並べ、「使える時間」を入力欄で変える。見積もりのないものの件数は、合計の下の文で示す。実行中の画面では容量の超過を判定しない（容量の判定は Planning だけ。Sprint 中の追加でも警告しない）。
- 計画のルールは、確定したときに使ったかどうかを読み取り専用で出す（不変条件 37）。ルールが効く計画値が 1 件もなかった Sprint（確定時には使わない。ドメインモデル F42）では、枠にせず「計画のルール「研究：見積もりの提案の上限で計画する」 · 対象なし」の 1 行（`help`、`ink-muted`、`info` のアイコン）にする。ルールが効く計画値があり、使わないと選んだ Sprint は枠のまま（Issue #161・#162）。

#### 日ごとの記録（Issue #53。入口・取り消した後の状態・期間はオーナーが決め、確認 Dialog と文言は実装で決めた）

- 実行中の Sprint の画面に「日ごとの記録」を置き、昨日までの日ごとに、完了とスキップを新しい日から並べる。各行に「取り消す」。見返すための一覧なので、Today の「取り消す」と同じ `undo-2` の IconButton（ラベルと Tooltip は「取り消す（完了）：9/29 (火) 住民税の支払い」）にし、どの幅でも常に見せる（Issue #160）。
- 取り消す前に確認 Dialog を出す（「9/29 (火) の「住民税の支払い」の完了を取り消しますか？」、説明に「その日の記録は未完了に戻り、タスクは今週の残りに戻ります。取り消したあと、その日の記録をもう一度完了にはできません。」、ボタンは「キャンセル」「完了を取り消す」（スキップなら「スキップを取り消す」））。取り消したら Toast で伝え、フォーカスは「日ごとの記録」の見出しに戻す。
- 取り消した日は未完了（Unresolved）になる。ただし、見送り・今日はここまで・予定から外した の後にその日のうちに完了した日は、その閉じた状態に戻る（F17）。Backlog からの完了で作った記録は、その日の記録ごと消える（F29）。Dialog の説明もこの 3 通りで書き分け、繰り返しなら後半を「繰り返しは未完了に戻ります。」にする（未完了に戻るときは「その日の記録と繰り返しは未完了に戻ります。」と 1 文にする。Issue #205）。取り消せるのは Sprint 中だけで、Review に入ったら Retro の事実として扱う（ドメインモデル F33）。

### Planning の最初の実装で決めたこと

Issue #40 でオーナーが決めた（2026-09-27〜28）。

- 確定前の計画の時間（プレビュー）は実線で描く。本人の選択から計算した値なので、破線（本人がまだ決めていない値：Agent 提案と下書き）にはしない。元が提案なら、値が同じでも提案（破線）と計画の時間（実線）を並べる（繰り返しの Task の提案は 1 回あたり）。
- 整える・確かめる段階の左の Backlog は、タイトルだけの `pane-list-slim`（240px）にする。選ぶ段階は `pane-list`（384px）。どちらも 1920px 以上では広げる（上の「大きい画面」）。
- 左の Backlog ペインの行は、medium 以上でもタイトルを 1 行で省略しない。選ぶは 2 行まで折り返し、見積もりの提案などの Estimate はタイトルの下、メタ情報と同じ行の右端に置く（入らなければ次の行の右端）。整える・確かめるの細い列はタイトルだけで、全文を折り返す。似た名前の Task を見分けられるようにするため。Issue #158（2026-10-01、オーナーの依頼）。
- 選ぶ段階の期限のグループは「期限切れ」（今日より前に期限がある Task）と「期限が近い」（今日から、計画中の Sprint の最終日までに期限がある Task）に分ける。Backlog の絞り込みと同じ分け方だが、「期限が近い」の終わりは今日を含む Sprint ではなく計画中の Sprint の最終日（F28 は変えない）。見出しに最終日を添える（「期限が近い · 〜10/11」）。持ち越しの Task は期限切れでも「持ち越し」に入る（1 つの Task は 1 つのグループだけ）。Issue #151（オーナーの決定、2026-10-01）。
- 容量のバーの下線は、下限でも超える場合だけ `danger` の実線、上限側だけ超える可能性がある場合は `warning` の破線にする。
- 今週に選んだ Task を Planning 中に完了・アーカイブしたら、その行に「完了済み」「アーカイブ済み」と「今週から外す」（繰り返しの Task は今週の回をすべて外す）を出し、確定ボタンの近くに理由を出す。自動では外さない（確定には外すことが要る）。

### 確定

- Primary「Sprint を確定」（⌘/Ctrl+Enter）→ Dialog（md）で要約：Area ごとの Goal、Task の件数（うち目標に入っていない件数。確かめるの要約と同じく Goal のある Area の分だけ。Issue #159）、計画の合計、使える時間、計画のルールを使うか（ルールが効く Task がないときは出さず、確定しても使わない。Issue #161、ドメインモデル F42）、注意（tight / over、見積もりなし）。
- ボタンは Secondary「戻って調整」と Primary「Sprint を確定」。初期フォーカスは「戻って調整」。
- 前の Sprint の Retro が終わっていなければ、確定ボタンを無効にし、理由（「前の Sprint の振り返りを完了すると確定できます。」）と振り返りへの導線を添える。下書きの編集はできる。
- 確定後：Toast「Sprint 14 を確定しました」、Status を「進行中」（実線）に、Today への導線（開始日より前に確定したときは「今日を開く」を出さず、確定した Sprint の画面に留める。Today は開始日まで読み取り専用で、Issue #156）。Goal の文と可用時間は確定後も変えられ、変更は履歴に残る（Dialog に「目標と使える時間はあとからでも変えられます。」）。

### compact

段階ごとに画面を分けてよいが、どの段階にも自由に移れ、「次へ」を必須の順路にしない（DESIGN.md Layout）。Capacity は整える・確かめるの画面上部に 1 行（「残り 1 〜 3h · 収まる」「超過 3 〜 5h · 少なく済んでも超える」。差が 0 をまたぐときは「少なく済めば 2.25h 残る · 多くかかれば 0.75h 超える」）で見せ、押すと時間の見通しを開く。確かめるは、中央の先頭の要約で全体を見せ、上の 1 行には数字を出さず「時間の見通しを開く」だけにする（要約と同じ数字を続けて出さない。Issue #165・#139）。

## Today

毎日使う軽い画面。日次の計画やタイムトラッキングにしない。スマートフォンで完結すること。

- 上部：「Sprint 14 · 2日目 / 7日」（`meta`）、日付（`display-m`「9月29日（火）」）、Progress（「今週の完了 5 / 18件」）。今日の残り件数と時間の合計を出してよいが（「今日の残り 3件 · 4–6h」）、日次の容量を入力させたり超過を判定したりしない。
- 今週の Goal を `reflection` で Area の路線記号付きで背景として見せる（Goal のない Area は出さない）。主役は「今日やる」のタスク。wide では右の列、medium では Progress の下、compact では今週の残りの後に置く（Issue #100）。
- **今日やる**：本人が「今週の残り」の行の先頭に常に見える「今日へ」のボタンで選ぶ（□ は使わない。UI v0.1 モック）。当日発生する繰り返しの回は、Planning で外していなければ自動で出る。前日に「今日はここまで」にした Task は「昨日の続き」として候補の上に出すが、自動では入れない。
- **日次の操作**：完了（○）を常時見せ、それ以外はメニューと詳細から。
  - 開始
  - 完了：○ が塗られ、タイトルが `ink-subtle`＋取り消し線。Toast は出さない。もう一度押すと取り消し。
  - 今日はここまで：作業したが未完了。任意でかかった時間を記録できる。
  - 今日は見送る：今日やらないと本人が決めた。
  - 今日の予定から外す：選び直し。見送りには数えない。
  - スキップ：繰り返しの回だけ（○ に「−」＋「スキップ」）。行の「取り消す」で戻せる（ドメインモデル F19）。
  - 「今日はここまで」「今日は見送る」「今日の予定から外す」にした行も、その日のうちなら ○ で完了にできる（ドメインモデル F17）。完了を取り消すと元の閉じた状態に戻る。
  - 「今日は見送る」「今日の予定から外す」にした行は、その日のうちなら行の「取り消す」で「今日やる」に戻せる（ドメインモデル F37）。開始してから見送った行は、開始したままに戻る。「今日はここまで」は取り消せない。
- 同じ Task を選んだ機会で見送りが続いたら「N回続けて見送り」と中立に出す（`ink-muted`）。
- **かかった時間（実績時間）**：任意。完了後か「今日はここまで」のときに軽く追記できる。ストップウォッチを必須にしない。
- **追加**：画面下部の sticky 入力「今日やるタスクを追加」（タイトルと Area 程度）と「追加」ボタン（Issue #98）。追加した Task は Sprint 中の追加として今の Sprint に入り、同時に「今日やる」にも入る（不変条件 26）。
- **割り込み**：Task の行とは別の入口（「割り込みを記録」）から、短いメモと任意の時間を Bottom Sheet で残す。記録しても今日の予定を組み替えない。
  - 面は、compact では Bottom Sheet、medium 以上では右の Drawer で、どの幅でもモーダルにする（暗幕を出し、Tab を中に閉じ込め、閉じたら開いたボタンに戻す。medium 以上では暗幕のクリックで閉じない。Issue #153。[アクセシビリティ](accessibility.md) のフォーカス）。
  - 入口は、どの幅でも上部の今日の残りの行の右に置き、スクロールせずに記録できるようにする。今日の残りの行を出さない朝も同じ位置に残す（Issue #100）。記録した割り込みの一覧は今週の残りの後に置き、記録がない日は出さない。

### 今日の行の操作（Issue #163）

2026-10-01 の初見ユーザー評価から、オーナーの依頼で起票した Issue #163 で決めた。補足の文言はオーナーが PR #178 の相談を受けて決め直した（Issue #163 のオーナーのコメント、2026-10-01）。方針は、説明文をうまく書くより、ラベルだけでなるべく区別できるようにし、説明は必要な場所だけに残す。

### どの日も開く（Issue #90）

- 日付の見出し（`display-m`）の左右に、前の日・次の日へ移る矢印（DESIGN.md Sprint Header と同じ形のリンク。「前の日：9/30 (水)」）を置き、見出しの右に「日付を選ぶ」（ネイティブの日付の入力）を置く。見出しの上は、その日を含む Sprint があれば今日と同じく「Sprint N · M日目 / 7日」。ない日も行の高さを残す。

## Retro

Planning と同じくらい重要な体験。反省文や成績表ではなく、**今週の事実から次の Sprint で試す変更を 1 つ決める** 場所。1 つの workspace が **事実を見る → 振り返る → 引き継ぐ** と変化する。Thinking space（`display-m` の見出しと `reflection` の本文、`spacing.8`〜`spacing.12` の余白、読み物は最大 720px）。

### 事実を見る

- 見出し「Sprint 14 で何が起きたか」（週の呼び名に従う。Issue #90）。最上部に Sprint Summary（完了 / 持ち越し / スキップ / 週の途中の追加 / 計画の合計と使える時間）。実績は入力済みのものだけと補足に書く。
- 見出しの下に、「振り返りに使う」の案内を 1 行置く（「気になった記録に「振り返りに使う」を付けると、「振り返る」で材料として並びます。」。付けなくても進めることは文にしない。Issue #208）。完了した振り返りには置かない（印を付けられないため。Issue #108）。
- 持ち越しは、表と compact の縦積みの結果に、`corner-down-right` と「持ち越し」を `ink-muted` で示す。完了は語だけ。`danger` は使わない。Summary の「持ち越し」にも同じアイコンを付け、件数が 1 件以上のときは件数を押せる（下線付きのリンクの見た目）。押すと持ち越しの Task の行（タイトル）にフォーカスが移り、続けて押すと次の持ち越しの行へ、最後の次は最初へ移る。0 件のときは文字だけ（Issue #108。移り方は実装で決めた。オーナーの確認は PR で取る）。
- 今回の計画のルールは 1 行だけ：「今回の計画のルール：「研究：見積もりの提案の上限で計画する」（扱いは「引き継ぐ」で決めます）」。結果は、扱いを選ぶ引き継ぐに出す（Issue #107）。
- Area ごとに：Goal 文（`goal`）と自己判定（RadioGroup「できた / 一部できた / できなかった / 決めない」、既定なし）、Task の表（Estimate / 計画 / 実績 / 結果）、目標に入っていなかった Task、繰り返し（完了 / スキップ / 未完了）、Sprint 中の追加、見送り・ここまで、割り込み（Retro の事実なので、「今日はここまで」を「ここまで」と書く。Issue #168）。
- Goal と可用時間を Sprint 中に変えていれば、確定したときとの差を出す。
- 計画との差は事実として語で出し、色（`danger`・`warning`）や評価の語で飾らない（Issue #167。使える時間との比べ方はオーナーが決めた。ほかの出し方は実装で決め、オーナーの確認は PR で取る）。
  - 要約の「計画 → 実績」の下に、確定したときの使える時間と比べた関係を、確定したときの計画の合計と、週の途中の追加を含めた合計の 2 行で並べる（「確定したときの計画 15.25–17.25h：少なく済めば 1.75h 残る · 多くかかれば 0.25h 超える」「週の途中の追加を含めて 17.25–20.25h：少なく済んでも 0.25h 超える」。収まるときは「多くかかっても 1h 残る」）。確定の後に計画が変わっていない（2 つの合計が同じ）ときは 1 行だけにし、外したタスクがあれば 2 行目は「外したタスクを除いて」と書く（Issue #167 のオーナー決定、2026-10-01）。
  - 要約の「計画 → 実績」の下に、割り込みの件数と時間の合計を 1 行で出し、実績に含まないことを添える（「割り込み 2件 · 合計 1.08h（実績には含みません）」）。時間を記録していない割り込みは「時間の記録なし 1件」と数える。
  - Task の表では、実績の下に計画との差を出す（「計画と同じ」「計画より 30m 少ない」、幅のある計画には「計画の幅の中」「上限より 1h 多い」「下限より 30m 少ない」）。実績が未入力のとき、計画が見積もりなしのときは出さない。compact の縦積みと振り返りの材料の値にも同じ語で出す。
- 「振り返りに使う」のオンは、トグルのオンと同じ墨の反転にし、ピンの代わりにチェックを出す（DESIGN.md Selected）。「次へ：振り返る」の横に付けた件数（「振り返りに使う 2件」）を出す。完了した振り返りには出さない（Issue #167）。
- 割り込みは日付と時刻で書く（「9/30 (水) 14:02」）。事実の一覧と振り返りの材料の両方（Issue #108）。
- Planning で外した繰り返しの回は出さない。
- 気になった事実に「振り返りに使う」の印を付けると、振り返りの材料に集まる。印を付けなくても次へ進める。材料の Task の行には表と同じ値を添える。タイトルの下に、Task Metadata の形（`meta`、値どうしは間隔だけで区切る）で「持ち越し（アイコン付き）　計画 5h（ルール）　実績 4.5h」と並べる。実績がなければ「実績 未入力」。割り込みなどほかの材料も、本文の下に日付や時間を同じ形で並べる。値は 1 つずつ次の行へ移し、値の途中や 1〜2 字だけ折れない（本文は文節で折る。読み上げるボタンの名前は「 · 」でつなぐ。Issue #108・#127）。操作の「振り返りに使う」が並べて収まらない幅では、文言の下に置く。
- 事実を見るでは、右側に振り返りの材料を出さない（印は各行に出ている）。材料は振り返る・引き継ぐで出す。空いた幅は Task の表と繰り返しの回に使い、Goal 文・要約などの文は 720px の列のまま（Issue #73 でオーナーが決めた、2026-09-29）。
- Task の表はどれも同じ列幅にして、Goal をまたいで列を揃える。wide では操作（振り返りに使う・かかった時間を記録）を横に並べ、結果は「 · 」の区切りでだけ折り返す。Goal の「振り返りに使う」は、表の操作の列と同じ右端に置く（Goal 文は `measure-read` のまま。オーナーの指摘で決めた）。medium で収まらないときは表を横にスクロールする（Issue #73 の実装で決めた。オーナーの確認は PR で取る）。

### 振り返る

- 入力は基本的に 2 つ：「気づいたこと」（任意。うまくいったこと、気になったこと）と「次に試すこと」。長い KPT や持ち越しの理由を求めない。
- 事実（`body`）と本人の振り返り（`reflection`）を分ける。Agent は事実を根拠に問いや文案を出してよいが、原因を本人の代わりに断定しない（Agent の見立ては破線、本人が加えるまで `body`）。

### 引き継ぐ

- 持ち越しがある Sprint だけ、先頭に「持ち越し N件」の見出しと、持ち越す Task のタイトルを並べる（5 件を超えたら先頭の 5 件だけを出し、「ほか N件を表示」で開く）。次の計画にすでに入っている Task、完了・アーカイブした Task には、行の末尾にその事実だけを添える（F35、Issue #107）。まだ Backlog に残っている Task があるときだけ、その下に行き先を 1 行で書く：「次の計画の「選ぶ」で決めます。」に続けて、次の計画が始まっていればその Sprint へのリンク、始まっていなければ「振り返りの完了後に始まります。」。持ち越しは Retro では決めない（不変条件 20）ので、ここに選ぶ操作は置かない（Issue #169）。
- 次に試すことを 1 件、自然文で確定する（下書き →「次に試すことを確定」）。次の Planning の最初（選ぶ段階の右ペインの上部）に表示だけで戻る。
- 次に試すことが機械的に適用できる場合だけ、任意で計画のルールを作れる（MVP は「見積もりの提案の下限 / 中央 / 上限のどこで計画するか」と対象の Area だけ）。
- Active な計画のルールがあった Sprint では、使った / 使わなかったにかかわらず「続ける / 終える / 置き換える」を選ぶ。理由は求めない。選ぶまで Retro は完了しない。次回に有効なルールは最大 1 件。
- 選ぶ場所（見出し「今回の計画のルール」）の直前に、今回の計画のルールの結果（名前、確定したときに使ったか、結果。例：「見積もりの提案の上限で計画した研究のタスク 2件のうち、1件を持ち越し（計画 5h・実績 4.5h）」）を出す。選択肢の説明は、次の計画で起きることで書く（続ける：「次の計画でも、見積もりがない研究のタスクは、見積もりの提案の上限で計画します。使うかどうかは「確かめる」で選べます。」、終える：「次の計画では、このルールを使いません。」、置き換える：「次の計画では代わりに、（新しいルールの効果）。使うかどうかは「確かめる」で選べます。」）。説明はルールの値から作る（Issue #107、不変条件 39）。「幅のあるタスク」とは呼ばず、どう計画したかで言う（件数のない「続ける」「置き換える」の説明だけ「見積もりがない」を添える。置き換えるは「次の計画では代わりに、見積もりがない研究のタスクは、…」。新しいルールのプレビューは件数のある形「次の計画では、研究のタスク 2件を、見積もりの提案の上限で計画します（今の Backlog で）。」で、0 件のときだけ件数のない形「次の計画では、見積もりがない研究のタスクは、見積もりの提案の上限で計画します（今の Backlog にはまだありません）。」。Issue #206 のオーナー決定）。完了した振り返りでは、同じ節に結果と「「続ける」にしました。」を出し、事実を見るの 1 行は「（結果と扱いは「引き継ぐ」にあります）」にする。持ち越しの一覧は、完了した振り返りには出さない。
- ルールの設定、効果の説明、次回 Planning のプレビューは同じ値から作り、食い違わせない。
- 「振り返りを完了」（Primary）は、引き継ぐの末尾に置く。ほかの段階の「次へ：〜」と同じ位置で、Sprint Header には置かない。段階を進めるボタンの語は「次へ：振り返る」「次へ：引き継ぐ」（Issue #168）。事実を見る・振り返るには置かないので、どの段階でも画面の Primary は 1 つまで（Issue #106）。押せないときは、ボタンの下に押せない理由だけを出し、理由には選ぶ場所か操作する欄の語（上の「今回の計画のルール」、「置き換える」、「計画のルールにもする」）を入れる。押せるときは、次に試すことが空なら「次に試すことがないまま完了します。次の計画には何も出ません。」を添える。押せるときも押せないときも、ボタンの位置は変わらない。
- 「振り返りを完了」を押したら、Dialog（md）で確認する（取り消せないため）。タイトルは「Sprint 14 の振り返りを完了しますか？」、説明は「完了すると、書いた内容は変えられず、この Sprint にはかかった時間を記録できなくなります。」（F22。書いた内容を変えられないのは #90 の決定。Issue #168）。本文は、次に試すこと（なければ「なし」）、計画のルールの決定（なければ「なし」）、持ち越しの件数と今ある場所（なければ「なし」。例：「Backlog に 2件」。2 か所以上なら「5件：次の計画に 2件 · Backlog に 3件」。Task のタイトルは引き継ぐの先頭にある）。ボタンは「戻る」（Secondary、初期フォーカス）と「振り返りを完了」（Primary）。
- Retro を完了すると Sprint は閉じ、次の Sprint を確定できるようになる。途中で閉じても書いた内容は残る（ヘッダーに「書いた内容は、途中で閉じても残ります」）。

### ルール

- 失敗の言葉と、割合や点数での評価は使わない（[文言と用語](content.md)の原則の 10）。数値の比較は「計画 27h → 実績 24.5h（入力済み 11件）」の形。
- Retro は数分で終えられる量にする。

### Retro の最初の実装で決めたこと

Issue #42 でオーナーが決めた（2026-09-28）。

- Sprint Header の Status は「振り返り中」。
- 「振り返りを完了」を押せない理由は、[文言と用語](content.md)の「操作できない理由」の文言を使う。Issue #106 で、選ぶ場所を入れた文言に直した。
- 次に試すことが空でも Retro を完了できる。押せるときだけ、完了ボタンの下に「次に試すことがないまま完了します。次の計画には何も出ません。」と添える（Issue #106 で、押せないときは出さないことにした）。
- 完了ボタンは、最初は Sprint Header に置いたが、入力する列から遠く、押せない理由が見つけにくかった。Issue #106 のオーナーの決定で、引き継ぐの末尾に移し、押す前に確認の Dialog を出す（「引き継ぐ」に書いた）。
- Retro を完了した後は、振り返りの画面に完了したことと次に試すことを出し、「Sprint N の計画を始める」（Primary）を置く。押すと次の週の Planning を始めて Sprint の画面へ移る。Planning はすでに始まっていれば「Sprint N の計画を開く」にする。Issue #90 で、完了した後の画面は同じ振り返りの読み取り専用になり、このボタンは Sprint Header の右に置く（後に確定した Sprint がある古い振り返りには置かない）。引き継ぐの末尾（完了を押した場所）にも置く（Issue #168）。Sprint の画面では、このボタンを次の週（→ で開く）に置く。
- Goal の自己判定は円の形と語で示す（DESIGN.md Tag）。

Issue #111 で決めた（オーナーの確認は PR で取る）。

- ナビから開いたとき（URL に `stage` がないとき）の段階は、今の Sprint の Retro の記録から決める。次に試すことを書いてあるか、計画のルールの続ける・終える・置き換えるを選んでいれば「引き継ぐ」、気づいたことを書いていれば「振り返る」、どちらもなければ「事実を見る」。完了した Retro は「事実を見る」から開く。次に試すことは入力欄を離れたときに保存するので、保存されている次に試すことは確定したものとして扱う。段階を別に覚えることはしない。開いたら URL に `stage` を書く（履歴は増やさない）ので、開いた後に書く内容を消しても段階は動かない。URL で `stage` を指定したときは、その段階を開く。
次は同じ Issue の実装で決めた（オーナーの確認は PR で取る）。

- 段階の見出しは「今週、何が起きたか」→「何に気づいたか」→「次の Sprint に何を引き継ぐか」。段階は URL の検索パラメータに持ち、どこからでも開ける。Issue #90 で、最初の見出しは週の呼び名に従う。振り返り中と完了の Sprint はいつも「Sprint N」なので「Sprint 2 で何が起きたか」になる。
- desktop（1200px 以上）は、読み物の列（`pane-today`、720px）の右に振り返りの材料（`pane-side`）を置く。それより狭い幅では、振り返るの段階の最初に出す。
- 「気づいたこと」と次に試すことは、入力欄を離れたときに保存する（途中で閉じても残る）。「次に試すことを確定」は編集を終えて `goal` の大きさで見せる。次に試すことから計画のルールを作っている間は、空にできない。
- 自己判定の RadioGroup は語だけにし、判定したら Area の見出しの横に自己判定の Tag を出す。
- Retro から開く実績の面も、Today と同じく題を「かかった時間を記録」、ボタンを「記録する」にし、説明に行き先の日を書く（「9/28 (月) に記録します。」。Issue #108、#206）。
- Retro 中に足す実績は、その日（最終日を過ぎていれば最終日）の実績として記録する（F22）。繰り返しの Task は、「繰り返し」の一覧の各行の「かかった時間を記録」から回ごとに足し、その回を完了した日（なければ予定日）の実績として記録する。行にはその回の実績を出す（Issue #56 のオーナー決定）。
- compact（768px 未満）の Task の表は、表をやめて 1 Task ずつ縦に積む（Issue #57 のオーナー決定）。タイトル、「見積もりの提案 3–5h · 計画 5h（ルール） · 実績 4.5h」、結果と見送り・ここまでの回数、操作（振り返りに使う・かかった時間を記録）の順。medium 以上は表。
- Sprint Summary の項目は 完了（件）/ 持ち越し（件）/ スキップ（回。補足に繰り返しの完了と未完了）/ 週の途中の追加（件）/ 計画の合計（補足に見積もりなしの件数と使える時間）。
- 今回の計画のルールの結果（`criterionResult`）は、繰り返しの Task を含めない。繰り返しは回の数で見せる（F20）。
- 計画のルールにもするとき、最初の設定は今回のルールと同じ（なければ「見積もりの提案の上限で計画する」、すべての領域）。対象と幅の扱いは Select で変え、効果の説明と次回 Planning のプレビューは同じ値から出す（不変条件 39）。今回のルールと同じ設定の間は、下書きに「今回のルールと同じ設定です。変えないなら、オフにして「続ける」を選びます。」と添え、次に試すことから作るルールの見出しを「新しい計画のルール」にして、今回の計画のルールと区別する（Issue #107 の実装で決めた。オーナーの確認は PR で取る）。
