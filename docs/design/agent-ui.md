AI / Agent は **通常の Product UI の延長** として表現する。別世界（Gradient、Sparkle、紫、Glow、チャットバブル）にしない。区別は **破線・語・根拠の構造** で行う。部品の見た目は [DESIGN.md](../../DESIGN.md) の Components（Agent 提案、根拠、計画案の差分）。

## 視覚ルール

| 対象 | 表現 |
| --- | --- |
| Agent 提案（未確定） | 1px 破線 `proposal-border`、`kicker` のラベルで種類（見積もり / 目標 / 計画案。見積もりは「見積もりの提案」）、出所（Itera / 外部 Agent（MCP））と時刻 |
| 提案された値 | suggestion の Estimate（破線枠＋「見積もりの提案」）か `body` の文。確定した言葉の `goal` / `reflection` で組まない |
| 本人が採用した値 | 実線・ラベルなし。提案から採用したことは変更履歴に残す（Estimate の source） |
| 過去の実績からコードが作った幅 | EstimateSuggestion として扱い、suggestion の見た目（破線＋「見積もりの提案」）に出所「過去の実績から」を添える。4 つ目の値にしない |
| 根拠 | 根拠 / わからない点 / 参照していない情報 |

## 情報構造（例：Estimate の提案）

```text
見積もりの提案                                Itera · 10/1 (木) 14:02
対象：評価用データセットを整備する
2〜4時間  ふつう 3時間  提案      [0 ——[==|==]—————— 8時間]
根拠           過去の類似タスク 3件（実績 2時間 / 2時間30分 / 4時間）、タスクの説明
わからない点    調査範囲（対象データの件数が未定）
参照していない情報  カレンダーの予定（未接続）
使う：[2時間｜3時間｜4時間]  直して使う  使わない
```

## 振る舞い

- **自動で適用しない。** 本人が使う・直して使う・使わないのどれかを選ぶまで、Estimate も合計も Sprint の状態も変えない。提示中の提案は幅のまま計画値の元になり（Estimate がなければ提示中の提案の幅、どちらもなければ未見積。却下した提案は元にしない）、Capacity では破線のセグメントで示す（不変条件 8）。
- **採用と適用を混ぜない。** 提案の少なめ・ふつう・多めのどれかを本人の Estimate にするのが「採用」（Task の値が変わる。Backlog と Planning の Task 詳細で行う。画面の語は「使う：」と値（読み上げ名は「多めの 4時間を使う」）、「直して使う」。Issue #242）。計画のルールで今回の計画の時間を作るのが「適用」（Task は変わらない。Planning の確かめる段階で行う。画面の語は「このルールで計画する」）。画面でも別の言葉・別の場所にする（Issue #206）。
- 採用系のボタンは Secondary、それ以外は Quiet。Primary を使わない。
- 使う・直して使う・使わないの後は、その場に 1 行の結果を残す（「見積もりを 3時間にしました · 元に戻す」「提案を使いませんでした · 元に戻す」）。どれも直後なら元に戻せる（ドメインモデル F27・F30・F31）。
- 計画案（複数の変更）は計画案の差分で **行ごとに選んで** 反映する。反映しても Sprint は確定しない。Agent の計画案は Sprint を直接書き換えず、採用した項目だけが本人の操作と同じ検証を通る（不変条件 41）。
- データ不足：幅を広く出し、「類似タスクの履歴がありません」をわからない点に書く。数値を捏造しない。本人の概算入力を促す。
- 失敗：「提案を作れませんでした。手入力でそのまま計画を続けられます。」＋「もう一度試す」。Planning を止めない。
- Loading：「過去の類似タスクを調べています…」＋「取り消す」。
- **参照していないものを参照したように書かない。** 使っていないデータは「参照していない情報」に列挙する（PRD §9 の 18）。
- confidence（確率）を時間予測の精度として表示しない。「高精度」と書かない。

## 文言

- 「Agent 提案」「提案」「根拠」「わからない点」「参照していない情報」「元に戻す」で統一する。見積もりの提案のボタンは「使う：」と値（読み上げ名は「多めの 4時間を使う」）・「直して使う」・「使わない」と書き、「採用」「却下」と書かない（モデルの採用・編集して採用・却下。Issue #206）。
- Agent を擬人化しない（「考えています」「おすすめです」ではなく「調べています」「提案を作れませんでした」）。

## やらないこと

- 画面内の汎用チャット、ストリーミング表示の吹き出し、アバター（PRD §7：汎用チャットは MVP の必須要件にしない）。
- Agent の出力だけ別の書体・別の背景色・グラデーション枠にすること。
- Sparkle アイコン、「AI」バッジの多用。Agent の由来は出所の文字で示す。
