# 文言と用語

更新：2026-10-01（今日以外の日の見出しに添える「過去」「未来」、Issue #90）。2026-09-30（振り返りを完了できない理由に、選ぶ場所を入れた、Issue #106。画面の語を「振り返り」「見積もり」「目標」に揃えた、Issue #104。時間の用語の言い換え、Issue #105。Planning を「計画」と書く、PR #116 のオーナー決定。週の呼び名、Issue #90）。2026-09-28（Retro の Status の語と、完了できない理由の文言、Issue #42。可用時間との差の表記、Issue #40）。2026-09-26 に DESIGN.md v0.2 から分離し、PRD v0.2 / ドメインモデル v0.2 Final の用語に合わせた。

用語の意味の正本は [ドメインモデル](../domain/domain-model.md) の「用語」表。ここは画面での書き方を決める。モデル名（Retro、Estimate、SprintGoal など）とコードの識別子は英語のまま使い、画面には下の「画面の語」を出す（Issue #104）。Sprint と Backlog は、ナビと製品の骨組みの名前として英語のまま残す（Issue #104 のオーナー決定）。Planning は画面では「計画」と書く（PR #116 のオーナー決定）。

送り仮名は「見積もり」に揃える。

## 語り口

- 丁寧体（です・ます）で短く。感嘆符、絵文字、煽り（「今すぐ」「最強」）を使わない。
- 本人を主語にする（「あなたが決めます」「本人が確定するまで反映されません」）。Agent は「Agent」と呼び、擬人化しない。
- 失敗を責めない。持ち越しは「持ち越し」、自己判定は「できなかった」。「失敗」「遅れ」と書かない。
- 結果を言い切る Toast（「3件を今週に入れました」「Sprint 14 を確定しました」）。次にできることを添える（「元に戻す」）。「今週」は開いている Sprint の呼び名に従う（下の「週の呼び名」。実行中の Sprint があるあいだの次の計画では「3件を来週に入れました」）。
- 表記は「Sprint 14」。欧文を大文字だけで組んだ飾りのラベル（「SPRINT 14」）は使わない。
- 和文と欧文の間は半角スペース（「Sprint 14 を確定」）。数字と助数詞・単位は詰める（「3件」「2日」「1.5h」）。範囲は en dash でスペースなし（「2–4h」「9/28–10/4」）。使える時間との差（残り・超過）は、前後にスペースを入れた「〜」（「残り 1 〜 3h」「超過 3 〜 5h」）。差が 0 をまたぐときは範囲にせず、「下限なら 2.25h 残る · 上限なら 0.75h 超える」の 2 つの文にする（Issue #93）。曜日付き日付の範囲だけ前後にスペース（「9/28 (月) – 10/4 (日)」）。

## 用語

| 画面の語 | モデル | 意味と表記 |
| --- | --- | --- |
| Sprint | Sprint | 1 週間の計画単位。「Sprint 14」。カタカナにしない |
| Backlog | Backlog（ビュー） | active な Task の一覧。Sprint や Today に入っても消えない。今の Sprint に入っている Task には「今週」 |
| 計画 | Planning（Sprint = planning） | 次の Sprint の計画を立てること。「次の計画には何も出ません」「Sprint 14 の計画を始める」。画面に「Planning」と書かない |
| 領域 | Area | 仕事・研究など、本人が作る領域。画面では各 Area の名前を出し、「カテゴリ」と呼ばない。未設定は「領域なし」 |
| 目標 | SprintGoal | Sprint × 領域の「今週の終わりにどんな状態にしたいか」。「〜な状態にする」「〜を終える」。任意。見出しは「今週の目標」、入力は「目標を書く」 |
| 目標に紐づく / 紐づかない | SprintTask.goalLink | 短く出すときは「目標なし」でもよい。紐づかない Task も時間に含める |
| 見積もり | Estimate | 本人が確定した点の値。「3h」「30m」。入力欄は「見積もり（時間）」 |
| Agent の提案 | EstimateSuggestion | 製品が出す幅。「Agent の提案 2–4h」（破線）。誰の提案かを語で示す |
| 採用 | Estimate.source ほか | Agent の提案を本人の値にすること。見積もりでは提案の下限・中央・上限のどれかを選ぶ（「上限 4h を採用」、source に記録）。目標の文案や計画案の項目にも使う |
| 計画値 | PlanningValue | 今回の計画に使う時間。「今回は 5h で計画」。Sprint 確定時（追加分は追加時）に固定。語は残し、最初に出る Capacity の近くに「計画値：今回の計画に使う時間。見積もりは変わりません。」と添える |
| 計画基準 | PlanningCriterion | 前の振り返りで決めた、提案の幅のどこで計画するかのルール。名前は「研究：提案の幅の上限で計画する」（すべての領域なら「提案の幅の上限で計画する」）。語は残し、Planning の確かめるの枠に「前の振り返りで決めた、提案の幅のどこで計画するかのルール。」と添える |
| 適用 | CriterionUse.appliedAtConfirm | 計画基準を今回の計画値に使うこと。Switch は「今回の計画に使う」。見積もりは変わらない |
| 使える時間 | Sprint.availableHours | 今週、計画に使える時間（本人が入力）。「使える時間 18h」。確定後は「計画したときの使える時間」と「今の使える時間」 |
| 計画値の合計 | — | 計画値の合計（幅のまま）。「16.5–18.5h」 |
| 残り / 超過 | — | 使える時間 − 計画値の合計。「残り 1 〜 3h」「超過 3 〜 5h」。0 をまたぐときは「下限なら 2.25h 残る · 上限なら 0.75h 超える」 |
| 優先度 | Task.priority | 「高 / 通常 / 低」（「普通」と書かない）。行の Task Metadata には高と低だけ「優先度 高」「優先度 低」と出し、通常は出さない。並び・絞り込みには使わない（不変条件 5。Issue #97） |
| 持ち越し | SprintTask = CarriedOver | Sprint 終了時に未完了。「持ち越し 2回（Sprint 13から）」 |
| 繰り返し | RecurrenceRule / Occurrence | ルールで発生する Task と、その回。「毎週 土」「毎週 月・木」「平日 · 今週 2/5」 |
| 未処理 | DailySelection = Unresolved / Occurrence = Missed | 選んだまま日付が変わった / 繰り返しの回が Sprint 終了時に未処理。見送りには数えない |
| 昨日の続き | 前日の DailySelection = Paused（派生） | Today の候補の上に出す。自動では今日に入れない |
| 見積もりなし | 計画値の元がない | 「見積もりなし」。0h と書かず、合計に含めない。件数は「見積もりのないタスク 1件は合計に含まれていません。」 |
| 見積もりのないサブタスク | サブタスク合計で、見積もりのないサブタスクがある | 見積もりのある分の合計に件数を添える。「2.5h（見積もりなしが 1件）」。Task の行（Estimate）と Retro の表の計画値の列では、値の下の行に `meta` で「見積もりなしが 1件」と出す（行のタイトルの幅を残すため） |
| 今日へ / 今日やる | DailySelection | 今日やると選ぶこと |
| 過去 / 未来 | — | 今日の画面で今日以外の日を開いたとき、日付の見出しの横に添える語。今日には付けない。読み取り専用であることを文で言い直さない（Issue #90、PR #122） |
| 開始 / 完了 | DailySelection = Started / Done | — |
| 今日はここまで | DailySelection = Paused | 作業したが未完了。翌日「昨日の続き」 |
| 今日は見送る | DailySelection = Deferred | 今日はやらないと決めた。「N回続けて見送り」 |
| 今日から外す | DailySelection = Removed | 選び直し。見送りに数えない |
| スキップ | Occurrence / DailySelection = Skipped | 繰り返しの回だけ |
| 週の途中の追加 | SprintTask.origin = midSprint | 確定後に Sprint に入った Task。行には「週の途中で追加」 |
| 割り込み | InterruptNote | 予定外の出来事のメモ。Task ではない |
| 確定 | Sprint = Active | 本人が Sprint を確定すること。「Sprint 14 を確定」。Agent には使わない |
| 振り返り | Retro / Sprint = review | 事実を見る → 振り返る → 引き継ぐ。ナビは「振り返り」、Sprint Header の Status は「振り返り中」（Issue #42）、ボタンは「振り返りを始める」「振り返りを完了」 |
| できた / 一部できた / できなかった / 判断しない | SprintGoal.selfAssessment | 目標の自己判定。未選択は「未判定」 |
| 改善策 | RetroImprovement | 次の Sprint で 1 つだけ変えてみること（自然文、1 件） |
| 続ける / 終える / 置き換える | CriterionUse.retroDecision | 計画基準の振り返りでの決定 |
| Agent 提案 | EstimateSuggestion / PlanProposal | Agent が作った未確定の値・文・計画案。見出しは「Agent 提案 · 見積もり」 |
| 振り返りに使う | — | 振り返りの事実を見るで、事実に付ける印。付けた事実が振り返りの材料に集まる |

## 週の呼び名

Issue #90 で定めた（オーナーの確認は PR で取る）。画面の組み立ては [画面のパターン](patterns.md) の「どの Sprint も開く」。

- 実行中の Sprint があるあいだは、それを「今週」、その次の Sprint を「来週」と呼ぶ。
- 実行中の Sprint がない（前の Sprint が振り返り中か完了）ときは、次に始まる Sprint を「今週」と呼ぶ。
- どちらにも当たらない Sprint は「Sprint N」と呼ぶ（振り返り中の Sprint、過去の Sprint）。
- 見出し・案内文・Toast・読み上げ・行とグループの語の「今週」は、開いている Sprint の呼び名に置き換える（「来週、何を進めますか」「来週発生する繰り返し」「来週から外す」「来週 3回」）。「Sprint N」のときは、欧文の後に半角スペースを入れる（「Sprint 2 で何が起きたか」「Sprint 1 の計画と結果」）。
- 「今週」「来週」は画面を分ける単位ではなく、どの Sprint も同じ画面で開ける中の呼び名。例文（「今週、何を進めますか」「3件を今週に入れました」）は、ふだんの場合の例として書く。

## 日付と時刻

- 日付は「9/28 (月)」。見出しの日付は「9月29日（火）」（全角括弧）。範囲は「9/28 (月) – 10/4 (日)」。
- 相対は「あと2日」「今日まで」「2日超過」。「明日」「昨日」は 24 時間以内の記録にだけ使う。
- 時刻は 24 時間表記（「14:02」）。「2分前」は 1 時間以内だけ、それ以降は時刻。

## ボタンの文言

- 動詞で終える（「Sprint 14 を確定」「追加」「保存」「差分を確認」「元に戻す」）。
- 「OK」「はい / いいえ」を使わない。確認 Dialog のボタンは結果を書く（「戻って調整」「Sprint 14 を確定」）。

## 操作できない理由

ボタンを無効にするときは、近くに「何をすれば押せるか」を書く。責める言い方や「エラー」を使わない。

| 場面 | 文言 |
| --- | --- |
| Planning の確定（前の振り返りが未完了） | 前の Sprint の振り返りを完了すると確定できます。前の Sprint が実行中なら「Sprint 2 の振り返りは 10/4 (日) から始められます。」を続ける（F21、Issue #90）。 |
| Planning の確定（完了・アーカイブした Task が残っている） | 完了・アーカイブした Task を今週から外すと確定できます。（「今週」は週の呼び名に従う） |
| 次の週（計画を始める前。Issue #90） | 確定できるのは、前の Sprint（Sprint 2）の振り返りを完了してからです。Sprint 2 の振り返りは、最終日の 10/4 (日) から始められます。（振り返り中なら「Sprint 2 は振り返り中です。」と振り返りへのリンク） |
| Backlog の今日へ（Sprint の開始日より前。Issue #59） | Sprint 2 が始まる 9/28 (月) から選べます。（行のメニューでは「今日へ（9/28 (月) から）」） |
| 振り返りの完了（計画基準の決定がまだ。不変条件 36。Issue #106） | 上の「今回の計画基準」で、続ける・終える・置き換えるのどれかを選ぶと完了できます。 |
| 振り返りの完了（「続ける」のまま新しい基準の下書きがある。不変条件 35。Issue #106） | 上の「今回の計画基準」で「続ける」を選んでいるときは、「計画基準にもする」をオフにするか、「置き換える」を選ぶと完了できます。 |

改善策が空でも振り返りは完了できる（Issue #42 のオーナー決定）。押せるときだけ、完了ボタンの下に「改善策がないまま完了します。次の計画には何も出ません。」と中立に添える。押せないときは、押せない理由だけを出す（Issue #106）。
